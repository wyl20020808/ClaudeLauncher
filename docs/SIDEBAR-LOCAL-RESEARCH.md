# Claude 4.29.0 本地侧栏项目调查

日期：2026-10-28。基于 `origin/dev` 的 `cddbe82`，分支 `feature/sidebar-local-research`。本轮只有调查、开发验证脚本与受控实验，没有新增产品功能，也不发布版本。第一阶段只保存环境配置，未达到目标；用户追加授权后的第二阶段通过空归档记录验证了原生目录入口，见文末。

## 用户需要的效果

所有已创建账号，包括未运行、从未使用某个目录的账号，都能在 Claude 原生左侧看到公共项目目录，并在对应目录中新建各自的对话。只汇总启动器清单不满足需求。只在“选择环境”中出现目录也不满足需求。

只操作本地目录配置；不复制对话、凭据、账号身份、环境变量或权限设置，不请求云端项目／会话接口。

## 已确定的本地存储机制

对本机官方应用包进行只读、内存中的代码定位，没有提取副本或修改应用包。

1. 本地保存的环境写入各 profile 下的 `ccd-session-presets.json`。主进程创建名为 `ccd-session-presets` 的存储，按 `byAccount` 划分目录配置；`LocalSessionPresets.load` / `replaceAll` 是内部 IPC。目录的最小目标形态是 `{kind: "local", cwd: "绝对路径"}`。这不是公开的跨进程调用接口。
2. 渲染进程还保存 `persisted.ccd-session-presets.<accountUuid>` 等 localStorage 状态。本地环境使用 machine 分区，云端环境另用 roaming 分区，不能混拷。
3. 文件镜像载入受 `fileMirrored` 控制；已经完成镜像的缓存不会因为 JSON 新增一条记录就重新合并全部文件内容。后续 `replaceAll` 又可能按内存状态写回 JSON。因此不能把直接写 JSON 当成可靠更新协议。本轮没有修改或读取浏览器数据库来绕过该机制。
4. 原生侧栏的目录／环境分组由本地会话及归档会话记录生成。环境清单用于匹配和命名这些会话所属的分组；当前检查的代码路径不会为每个未使用的环境无条件生成空分组。已有目录只剩归档会话时仍可能显示分组，不代表完全没有会话记录的目录也能显示。
5. 从已有侧栏分组点击“新建”会调用 `stageEnvironment` / `stageEnvironmentForPlace`，把目录配置应用到新会话草稿。这说明分组存在时可以交接目录，不能证明仅登记目录就能创建分组。

## GUI 实测

在一个已运行的客户端内，通过官方界面创建了一个仅用于验证的本地环境，引用 `build/` 下随机命名的空目录。不发送提示词，不启动模型任务，不创建或复制会话记录，不退出客户端。

| 清理 | 在官方界面删除本次创建的测试环境；文件检查确认测试记录数量为 0；随机目录为空，已清理 |

只检查了已确认用途的 presets 文件中的测试元数据，没有打开会话存储文件、凭据文件或进程环境。没有修改系统权限、强杀进程或触碰登录状态。官方界面可能自行维护最近使用等状态；本轮不声称整个 profile 与测试前逐字节相同。

## 结论与实现边界

本地目录配置确实存在，但它不是独立控制原生侧栏项目列表的唯一来源。当前“追加本地环境配置”的方案已被 GUI 实测证明不足以满足要求；不能据此交付“侧栏同步”。

尚未找到在当前版本中，仅登记目录、不改会话存储或官方应用，就能让从未使用该目录的账号产生原生侧栏入口的可靠入口。不批量修改账号，也不加入一个明知达不到效果的写入功能。后续若发现其他本地配置入口，仍须按 SPEC 的原生侧栏标准验证后才能实现和发布。

## 第二阶段：全新空归档记录（用户追加授权）

用户提出只复制会话文件、删除内容、避免带入登录信息，并明确“宁愿不做也不要做错”。本轮没有复制真实会话文件，而是仅从一个新建空目录生成最小记录。

### 为什么不能复制原记录后只删消息

官方会话序列化代码还保留 `cliSessionId`、历史会话 ID、`stagedTranscriptPath`、`bridgeSessionIds`、`cloudSessionId`、远程配置、`remoteMcpServersConfig`、权限更新、`pendingFirstStart`、中断恢复及待处理任务等字段。删除聊天正文不足以解除这些关联；MCP 配置本身也可能含认证信息。因此没有打开真实会话的完整 JSON，来源路径识别仍只能使用既有的受限前缀读取方法。

实验记录只有七个字段：

```json
{
  "sessionId": "local_<全新 UUID>",
  "cwd": "<新建空测试目录的绝对路径>",
  "originCwd": "<同一目录>",
  "title": "项目目录入口（无对话）",
  "createdAt": 0,
  "lastActivityAt": 0,
  "isArchived": true
}
```

上面的 0 是示意，实验使用当前毫秒时间戳。记录不带 `cliSessionId` 或任何历史引用，也不创建 JSONL 聊天正文。官方 `iN` 反序列化对没有 CLI ID 的记录设置 `isFirstTurn=true`、空 `messageBuffer` 和未运行状态；实际 GUI 加载另行验证，没有把静态代码推论当作实测。

### 离线验证

`node scripts/check-sidebar-seed.cjs` 是开发专用探针，不编译或打包进启动器，日常应用仍不依赖 Node。它不访问真实账号、环境变量、凭据、网络或 Claude 进程；只读官方包内三个经过 SHA-256 固定的代码文件，在无文件／网络接口的 JS context 中运行选定的纯分组函数。

- 合成两个独立记录，验证字段白名单、不同 UUID、0600 写入与 JSON 往返。
- 使用合成事件适配器调用实际分组函数，验证一个目录分组、零活跃行、一条隐藏归档记录，以及正确的本地目录。
- 所有随机临时文件在 finally 中清理。包内代码变化或 Node 缺少解析器时失败，不猜测兼容性。
- 该脚本本身不测试完整后端加载或真实 GUI，输出明确保留这些未验证项；下面是独立进行的 GUI 结果。

> 历史阶段：本节主要调查下文称为路线 B 的 registerExternalSession / imported-staging。路线选择、内容丢弃规则、实验顺序及 cwd 处理以[第四阶段](#session-import-a1)的后续结论为准；本节的原始检查结果与当时的未验证项保留，不作为当前产品规格。

### 结论与证据等级

当前版本包含外部 Code 会话的本地导入与恢复准备逻辑。自行实现受限的本地文件转换，比直接调用未公开的内部入口更容易约束文件范围和网络行为，但尚不能宣称是已经验证的安全迁移方案。

- 已静态确认：桌面记录与 JSONL 分离；导入使用新的桌面／CLI 会话 ID；历史可以先暂存；继续前有确认状态；确认后将历史移入目标配置目录，随后使用 CLI 会话 ID 选择恢复。
- 已用合成输入执行：官方单条历史转换、工作目录提取、导入记录构造、压缩边界引用提取四个纯函数。它们不执行文件操作、启动、IPC、网络或完整 JSONL 加载。
- 尚未验证：自有导入产物能否被完整解析、显示、经用户确认后正确续聊。不能用静态字符串匹配或纯函数检查代替这三项验收。
- 不需要把语义压缩设为迁移前提。官方已审查的本地导入转换保留消息正文；长历史是否完整进入下一轮模型上下文，仍取决于底层加载／压缩机制。

### 两层存储和暂存阶段

常规桌面记录位于 `<profile>/claude-code-sessions/<account>/<org>/local_<desktop UUID>.json`。普通本地 Code 正文位于 `<Claude Code config>/projects/<cwd slug>/<cliSessionId>.jsonl`。01 的配置目录默认为 `~/.claude`；02～10 由启动器设置为各自 profile 下的 `ClaudeCodeConfig`。这些位置来自代码，不是本轮扫描真实账号得到的清单。

桌面记录中的 `sessionId` 标识侧栏会话，`cliSessionId` 关联正文。`cwd`／`originCwd` 指向工作目录，不能当作正文路径。导入暂存结构为：

```text
<target profile>/claude-code-sessions/<target account>/<target org>/
  local_<fresh desktop UUID>.json
  imported-staging/
    <fresh CLI UUID>.jsonl
```

暂存记录包含 `stagedTranscriptPath`。历史读取器在该字段存在时选择其父目录，再根据 `cliSessionId` 寻找 JSONL，因此文件名与记录 ID 必须一致。不存在暂存字段时才走常规 projects 解析路径。仅在项目根目录放一个同名文件不会自动形成原生会话。

这里的文件操作本身不需要网络。上述完整函数还依赖客户端状态、归属检查和其他模块，不能由此宣称调用官方导入入口全过程不联网，也不能当作公开 API。自有实现不调用这些函数或 IPC；最终发送由用户在官方客户端完成，不代发、不预热模型。

### 不能直接照搬的行为

1. **官方转换不是完整脱敏。** 合成反例中，顶层 emailAddress、未知私有字段及正文中的敏感标记都被 `q` 保留。移除 sessionId 不等于移除所有身份信息；更不等于正文没有秘密。
2. **不能把所有 UUID 都删除。** 合成主链的 uuid／parentUuid 和工具调用／结果对应关系在转换后仍保留。压缩边界还可能通过 preservedMessages、preservedSegment 引用消息。若要重新编号，必须一起更新所有已支持的引用；未知引用不能猜测。
3. **不能静默遗漏行。** 官方 `Z` 会跳过解析失败或没有 cwd 的行。这不适合作为我们“完整导入成功”的判据。自有实现需要明确行数、支持类型和拒绝原因；不能删除未知行后宣称完整保留历史。
4. **不能继承来源的执行设置。** 官方元数据构造函数虽然不复制任意来源字段，但可选参数仍能带入 launcherMarked、adoptedFromOtherSurface、cliMcpAppServerNames 等。自有实现应单独构造所需参数，不直接传来源对象。
5. **不能绕过继续确认。** `resumeConfirmed` 不在已检查的基础导入记录中；直接设置 true 会改变官方确认语义。必须保留目标侧确认，不能以“已导入”为理由继承来源信任或权限。
6. **不能沿用覆盖写入策略。** 官方确认方法含移动、复制和错误回退，其内部状态不等同于启动器的外部写入条件。启动器仍须使用目标不运行、路径复核、独占新建、绝不覆盖现有记录的规则。
7. **不能假定可恢复已丢失的上下文。** 会话可能有历史 CLI ID、分叉、回退、压缩段、子代理、外部附件及旧工作树。单个 JSONL 不必然包含可完整恢复的全部资料。

### 建议的实现边界（设计候选，未接入产品）

第一步只实现“单向、一次性、独立副本”，暂不做实时合并，也不增加 AI 摘要。目标账号已继续工作后，再导入应产生独立版本，不能覆盖其新增进展。

建议把以下条件作为后续原型的验收要求：

- 来源读取固定在用户选中的会话及经验证的正文位置；不读取登录配置、Cookie 或环境凭据，不用旧标识访问任何云端服务。正文可能由用户主动写入秘密，预览与字段过滤不能承诺自动识别全部秘密。
- 从已知记录类型和字段白名单重建内容。初始格式实验用短的线性纯文本会话，再扩展到完整的工具调用／结果配对；分叉、回退、子代理、图片／附件、压缩段在适配前明确拒绝或报告不支持，不自动转成有损导入。
- 来源快照须检查文件身份、边界和读前读后变化；拒绝半行、坏 JSON、重复／悬空消息关系与未知结构。读取有大小／条数上限，达到上限不得当作完整成功。
- 新建目标桌面／CLI ID；目标账号／组织目录必须唯一、安全且已存在，不从来源复制身份目录。运行中、启动中、登录保护中或归属不明确的目标拒绝写入。

- 不自动修改目标信任／权限、不设置 resumeConfirmed、不自动打开会话或发送。用户正常打开客户端后确认；客户端确认时具体显示什么、是否能续接必须另行实测。
- 保留每次导入的来源版本标记与结果计数以支持去重／提示更新；标记放启动器自身数据中，不将真实正文、身份或路径打印到普通日志。具体持久化格式尚未设计。

不增加产品读取范围或改变 SPEC。上面是待验证的设计，不是当前“同步到账号”已具备的行为。

### 路线与设计修正

- **A1 优先**：启动器只准备目标 Claude Code 配置目录 projects 下的独立 JSONL，由用户在官方界面确认批量导入；官方创建桌面记录并设置目标 homeTenancy。`index.chunk-C3r2jk0E.js` 的 `scanRecoverableCliSessions` / `mK` / `recoverCliSessions` 是这条路径，不调用 `adoptCliSession`。
- **A2 与 B 分开**：`importCliSession` / `adoptCliSession` 是单会话接管路径；B 是 `registerExternalSession` / `imported-staging`。不能混用它们的权限、确认或遥测结论。A1 不需要启动器手写账号／组织目录、importedFrom 或 resumeConfirmed；B 暂留研究备选。
- **目标配置目录**：`index.chunk-CfIZxb16.js::s` 在参数为空时使用 `GH()`；`index.chunk-m4oMImJ-.js::GN`（导出 GH）优先取当前进程的 CLAUDE_CONFIG_DIR，否则取 ~/.claude。启动器正常启动的 02～10 会得到各自 ClaudeCodeConfig；从其他入口启动或已运行进程的环境不能仅凭目录推断。

### cwd 规则修正与实现注意

会话中可能 cd 到子目录。修订为以**所选主链按会话顺序遇到的第一个有效 cwd**作为根目录，允许该根及其子目录归并为同一导入项目；主链工作目录落在根目录之外时拒绝。不取文件中其他分支最早出现的 cwd，不自动扩大到所有 cwd 的公共祖先来迁就跨项目记录。

实现时须按规范化、实际解析后的路径组件判断包含关系，不能用字符串前缀：`/project-other` 不是 `/project` 的子目录，指向根外的符号链接也不算子目录。根目录缺失、不可访问或解析不明确属于路径校验失败，不能把“根外才拒绝”解释成放行无效路径。首次有效 cwd 的确定和所有被使用路径仍须遵守已有项目路径保护边界。

归并目录不等于重解释文字或相对路径：工具说明中的相对路径应结合对应原 cwd 理解，再转换为根目录相对路径；正文中的目录语境不能丢失或未经确认改写。上述路径安全和语义处理是实现要求，尚未被这一个续聊样本全面验证。
