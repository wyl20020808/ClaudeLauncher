# Claude 4.29.0 本地侧栏项目调查

日期：2026-10-28。基于 `origin/dev` 的 `cddbe82`，分支 `feature/sidebar-local-research`。本轮只有调查、开发验证脚本与受控实验，没有新增产品功能，也不发布版本。第一阶段只保存环境配置，未达到目标；用户追加授权后的第二阶段通过空归档记录验证了原生目录入口，见文末。

## 用户需要的效果

所有已创建账号，包括未运行、从未使用某个目录的账号，都能在 Claude 原生左侧看到公共项目目录，并在对应目录中新建各自的对话。只汇总启动器清单不满足需求。只在“选择环境”中出现目录也不满足需求。

只操作本地目录配置；不复制对话、凭据、账号身份、环境变量或权限设置，不请求云端项目／会话接口。

## 已确定的本地存储机制

对本机官方应用包进行只读、内存中的代码定位，没有提取副本或修改应用包。

1. 本地保存的环境写入各 profile 下的 `ccd-session-presets.json`。主进程创建名为 `ccd-session-presets` 的存储，按 `byAccount` 划分目录配置；`LocalSessionPresets.load` / `replaceAll` 是内部 IPC。目录的最小目标形态是 `{kind: "local", cwd: "绝对路径"}`。这不是公开的跨进程调用接口。
2. 渲染进程还保存 `persisted.ccd-session-presets.<accountUuid>` 等 localStorage 状态。本地环境使用 machine 分区，云端环境另用 roaming 分区，不能混拷。
3. 文件镜像载入受 `fileMirrored` 控制；已经完成镜像的缓存不会因为 JSON 新增一条记录就重新合并全部文件内容。后续 `replaceAll` 又可能按内存状态写回 JSON。因此不能把直接写 JSON 当成可靠更新协议。本轮没有修改或读取浏览器数据库来绕过该机制。
4. 原生侧栏的目录／环境分组由本地会话及归档会话记录生成。环境清单用于匹配和命名这些会话所属的分组；当前检查的代码路径不会为每个未使用的环境无条件生成空分组。已有目录只剩归档会话时仍可能显示分组，不代表完全没有会话记录的目录也能显示。
5. 从已有侧栏分组点击“新建”会调用 `stageEnvironment` / `stageEnvironmentForPlace`，把目录配置应用到新会话草稿。这说明分组存在时可以交接目录，不能证明仅登记目录就能创建分组。

## GUI 实测

在一个已运行的客户端内，通过官方界面创建了一个仅用于验证的本地环境，引用 `build/` 下随机命名的空目录。不发送提示词，不启动模型任务，不创建或复制会话记录，不退出客户端。

| 步骤 | 观察结果 |
| --- | --- |
| 新建本地环境，选择随机空目录 | 保存成功；原生“新会话”页面的环境选择器中出现测试名称 |
| 检查该环境的落盘元数据 | `ccd-session-presets.json` 中存在正确名称和 `target.kind=local`、正确目录 |
| 保持“按文件夹分组” | 左侧没有测试目录分组 |
| 开启“显示 → 空分组” | 开关变为开启，左侧仍没有测试目录分组 |
| 改为“按环境分组”，同时保留空分组开关 | 左侧仍没有测试环境分组 |
| 画面核对 | 新会话页面能看到测试环境，左侧仍只有原先的项目；未达到用户验收标准 |
| 清理 | 在官方界面删除本次创建的测试环境；文件检查确认测试记录数量为 0；随机目录为空，已清理 |
| 恢复 | 分组恢复为文件夹，空分组开关恢复关闭，界面回到验证前打开的会话 |

只检查了已确认用途的 presets 文件中的测试元数据，没有打开会话存储文件、凭据文件或进程环境。没有修改系统权限、强杀进程或触碰登录状态。官方界面可能自行维护最近使用等状态；本轮不声称整个 profile 与测试前逐字节相同。

## 结论与实现边界

本地目录配置确实存在，但它不是独立控制原生侧栏项目列表的唯一来源。当前“追加本地环境配置”的方案已被 GUI 实测证明不足以满足要求；不能据此交付“侧栏同步”。

尚未找到在当前版本中，仅登记目录、不改会话存储或官方应用，就能让从未使用该目录的账号产生原生侧栏入口的可靠入口。不批量修改账号，也不加入一个明知达不到效果的写入功能。后续若发现其他本地配置入口，仍须按 SPEC 的原生侧栏标准验证后才能实现和发布。

## 第二阶段：全新空归档记录（用户追加授权）

用户提出只复制会话文件、删除内容、避免带入登录信息，并明确“宁愿不做也不要做错”。本轮没有复制真实会话文件，而是仅从一个新建空目录生成最小记录。

### 为什么不能复制原记录后只删消息

官方会话序列化代码还保留 `cliSessionId`、历史会话 ID、`stagedTranscriptPath`、`bridgeSessionIds`、`cloudSessionId`、远程配置、`remoteMcpServersConfig`、权限更新、`pendingFirstStart`、中断恢复及待处理任务等字段。删除聊天正文不足以解除这些关联；MCP 配置本身也可能含认证信息。因此没有打开真实会话的完整 JSON，来源路径识别仍只能使用既有的受限前缀读取方法。

实验记录只有七个字段：

```json
{
  "sessionId": "local_<全新 UUID>",
  "cwd": "<新建空测试目录的绝对路径>",
  "originCwd": "<同一目录>",
  "title": "项目目录入口（无对话）",
  "createdAt": 0,
  "lastActivityAt": 0,
  "isArchived": true
}
```

上面的 0 是示意，实验使用当前毫秒时间戳。记录不带 `cliSessionId` 或任何历史引用，也不创建 JSONL 聊天正文。官方 `iN` 反序列化对没有 CLI ID 的记录设置 `isFirstTurn=true`、空 `messageBuffer` 和未运行状态；实际 GUI 加载另行验证，没有把静态代码推论当作实测。

### 离线验证

`node scripts/check-sidebar-seed.cjs` 是开发专用探针，不编译或打包进启动器，日常应用仍不依赖 Node。它不访问真实账号、环境变量、凭据、网络或 Claude 进程；只读官方包内三个经过 SHA-256 固定的代码文件，在无文件／网络接口的 JS context 中运行选定的纯分组函数。

- 合成两个独立记录，验证字段白名单、不同 UUID、0600 写入与 JSON 往返。
- 使用合成事件适配器调用实际分组函数，验证一个目录分组、零活跃行、一条隐藏归档记录，以及正确的本地目录。
- 所有随机临时文件在 finally 中清理。包内代码变化或 Node 缺少解析器时失败，不猜测兼容性。
- 该脚本本身不测试完整后端加载或真实 GUI，输出明确保留这些未验证项；下面是独立进行的 GUI 结果。

### 单账号 GUI 与回滚实测

1. 用户正常退出账号 02；启动器的进程诊断确认 02 不运行。仅通过目录元数据确认该 profile 下只有一个账号／组织存储位置，没有读取凭据来识别身份。
2. 逐级 `O_NOFOLLOW` 打开目标目录，复核所有权和写权限；再次确认 02 未运行后，以 `O_EXCL`、0600 新建一个随机命名记录。没有覆盖或读取任何原有会话文件。测试目录位于用户主目录下，是独立随机空目录。
3. 通过现有启动器的账号 02 按钮启动。界面工具不能区分两个同名运行实例；经用户确认正常退出 01 后，仅验证 02。
4. “空分组”关闭时未显示测试目录；开启后，原生左侧立即出现该目录并显示“无活跃会话”。原有“本电脑／对话测试”仍在。
5. 点击测试目录的“新建会话”，出现“信任此工作区？”对话框，路径准确指向测试目录。选择取消；没有授予目录信任，没有发送消息，没有启动模型任务。
6. 正常退出并经启动器重启 02，测试目录仍在，仍显示“无活跃会话”。记录文件大小保持 299 字节，测试目录仍为空。
7. 再次正常退出 02，只删除实验新建的那个记录和空目录。重启后，在“空分组”仍开启时，测试目录分组消失；原有会话入口仍在。
8. 将“空分组”恢复关闭，将新会话文件夹选择恢复为验证前的 `~/Desktop/ClaudeLauncher`。最近目录菜单中不再显示测试目录。02 保持运行，01 保持未运行。

测试过程中，界面工具在检查已退出应用时自动打开过一次默认实例；随即正常退出该实例，并通过进程诊断确认没有其他 Claude 主进程，再继续测试 02。没有强杀进程，没有退出登录。

### 第二阶段结论与未验证项

此版本上，“全新空归档记录 + 显示空分组”能产生用户需要的原生目录入口，并通过一次正常重启及移除回滚验证。第一阶段关于仅保存环境配置不足以显示侧栏的结论仍成立；新的实验改变的是分组所需的本地记录。

取舍是每个项目、每个目标账号都需要保留一条空归档记录；它不是纯目录配置，可能在归档会话列表中可见。没有聊天正文或旧账号 ID，不代表官方已提供或承诺兼容这种用法。

- 已验证：真实侧栏入口、零活跃会话、新建入口传递准确目录至信任确认、正常重启持久化、删除实验记录后的分组消失。
- 未验证：接受信任后的完整草稿流程及真实发送、多个目标账号／项目的批量处理、长期保留与官方自动清理、未来版本兼容、客户端是否对该记录进行后台联网处理。
- 没有做“账号不会受限制”或“整个客户端零联网”的保证。实验文件生成没有网络请求；官方客户端的后台行为没有抓包验证。
- 没有产品源码变更，未构建、未打包、未发布，未把实验入口接入公共项目管理。现有账号隔离机制保持不变。
