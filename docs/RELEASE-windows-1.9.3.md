# Windows 1.9.3

修复打开账号时误报“账号存储隔离检查未通过：存储项与账号目录外的文件共用硬链接”，并收紧硬链接检查。

- 误报原因：Claude Code 会把子代理记录 `ClaudeCodeConfig\projects\…\<会话 ID>\subagents\agent-<代理 ID>.jsonl` 和临时目录里的后台任务输出 `%TEMP%\claude\…\<会话 ID>\tasks\<代理 ID>.output` 做成同一个文件（硬链接）。这是官方正常行为，不是账号之间共用数据。现在这种关系放行：会话 ID 和代理 ID 必须对得上，路径形状必须完全符合。
- 检查更严：同一个文件的所有名字都要合规才放行。账号内只允许会话备份（`file-history`）和会话／子代理记录的位置；登录存储、设置、缓存或其他账号的名字混进来一律提示风险。临时目录被重定向、目录所有者异常，或检查过程中文件一直在变，会提示“无法确认”，不当作通过。
- 同步会话不放宽：读取来源和替换目标仍要求独立文件，打开账号时选“仍然继续”不影响同步的检查。
- 建分组后去掉标题前缀：“打开并建分组”预填的指令会让目标账号的 Claude 建好分组后，把副本标题开头的「【分组名】」去掉（组名已经显示在分组上）。只改已在该分组、标题正好以此开头的会话；启动器仍只预填，不代你发送。

不新增 Claude／Anthropic 访问，不新增网络入口；只读文件元数据，不打开文件内容。程序和安装包仍未签名（Authenticode）。macOS 未改，仍可能出现子代理记录的同一误报。
