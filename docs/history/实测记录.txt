测试边界
只使用账号 01 和 02，没有开满 10 个账号，没有输入凭据或替用户登录。
开始时没有 Claude 桌面主进程，已有默认 Claude 数据目录。通过界面打开默认 Claude 后，确认原账号已登录；随后用启动器识别该实例。
账号 01 主进程 PID 7747；新建账号 02 主进程 PID 8633。以下记录将真实界面观察、进程观察和静态检查分开，不把请求成功当作窗口恢复成功。

1. 已运行账号切回原窗口：未完整通过。
实际点击了账号 01、02；启动器准确显示对应 PID，启动参数映射检查正确。观察到系统前台 PID 未可靠切换到指定实例，因此不能认定“准确切回”通过。已实现按 PID 的 NSRunningApplication 激活、macOS 14+ 激活交接，以及授权后的 AX 窗口提升。后者仍受权限状态阻碍。

2. 重复点击不新增实例：通过所测路径。
多次点击运行中的账号 01、02，进程核验始终各一个主进程，PID 分别为 7747、8633。账号 02 首次启动时界面实际显示“正在启动…”且按钮 disabled。没有刻意做高频自动化点击压力测试。

3. 未使用账号创建目录并显示独立登录页：部分通过。
点击账号 02 前目录不存在，界面为“首次使用”。点击后创建 Claude-Second，生成带指定 user-data-dir 的独立主进程 8633，状态转为运行中。未使用账号 03～10，没有创建这些账号目录。
独立登录页未验证：当前 macOS 自动化工具按 bundle ID 绑定同名应用时始终选中默认实例，不支持按独立窗口 ID 绑定第二个实例。没有将默认账号界面误记为账号 02 登录页。

4. 隐藏和最小化后恢复对应窗口：未验证。
执行了隐藏和最小化测试动作，但未获得可靠的恢复前后证据。用户已手动授权，并重新授权；系统设置截图显示启动器开关为 on。最终应用自身仍报告“窗口恢复权限尚未启用”。已退出启动器、重新启动，也通过 Finder 双击重开，结果相同。随后只读查询系统 TCC 日志，确认“Failed to match existing code requirement”：旧授权指纹为 ddf030987a3baf0dba71bc53c9a62b973ae0719a，定稿应用指纹为 0ae82ff71a5a011b88ead959ab772105a4d7d8bb。根因为重建后的签名与旧授权记录不一致，不是用户没有打开开关。已停止重建，未修改 TCC 数据、绕过权限或重启 Mac。不能将已实现的 AX 恢复代码计为实机通过。

5. 重复打开启动器仅一个管理窗口：通过所测路径。
通过 Finder 连续双击两次应用，界面维持一个管理窗口，进程检查只有一个 ClaudeLauncher。另有 flock 单实例保护处理直接重复执行的情况；未对同时启动多个副本做竞态压力测试。

6. 关闭启动器不关闭 Claude：通过。
点击启动器关闭按钮后，Claude PID 7747、8633 继续存在。还通过 Cmd+Q 退出启动器并重新打开，两账号 PID 保持不变。未结束 Claude 或退出任何账号。

7. 原目录和原登录状态：确认保留，非逐文件不变校验。
默认账号界面显示原已登录账号，测试中未执行登出或登录操作。默认目录 inode 始终为 1762871，创建时间标识为 1792033836，没有替换、迁移或删除目录。
启动器没有读取、复制或写入既有目录内的登录文件。Claude 自身正常运行可能更新缓存、会话和日志，未读取凭据做哈希或逐文件比较，因此不声称目录内所有字节完全未变。最终登录状态未做第二次单独验收。
