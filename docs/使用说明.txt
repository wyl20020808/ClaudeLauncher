Claude 启动器 1.7.3 / build 10（2026-10-28；发布状态见 docs/STATUS.md）

安装：打开 DMG，把「Claude 启动器」拖到「应用程序」。首次打开若提示无法验证开发者，在 Finder 中右键应用选「打开」，或到「系统设置 → 隐私与安全性」点「仍要打开」。日常不需要终端、Python 或 Node.js。支持 Apple 芯片与 Intel，macOS 12 及以上。
只显示本机已有的账号，每个账号一张卡片，主按钮为创建、启动或打开；正在启动时按钮禁用。“+ 新建实例”会创建第一个尚未使用的编号。卡片右侧“···”可在 Finder 中显示或复制账号目录。关闭启动器不会退出 Claude。

用量记录（macOS 实验分支 codex/usage-limits-research，尚未发布／安装）
打开启动器、切回前台或返回实例页时，读取各目录内官方 Claude 已保存的 plan-usage-history.json，不另发限额查询，不自动操作官方界面，不读取登录凭据。后台不轮询。
“5小时限额”“周限额”显示的是已用百分比，底下明确标“本地记录 · HH:mm”；悬停可看完整日期和限制。历史文件不证明当前登录身份，也没有重置时间。记录超过 15 分钟时显示“记录已过期”，有多个组织时显示“身份待核对”；缺失、未知格式、登录保护或进程识别异常也不显示数值。不会把未读取到的值显示成 0%。
需要实时值时，请在官方 Claude 点击“用量”。官方历史最短约 4.5 分钟才追加一次，所以即使官方弹窗已更新，启动器仍可能暂时没有新记录。软件不会为了获得数字而发消息、消耗模型额度或触发后台查询。本地读取没有新增查询请求，但不能据此承诺整个账号零封号风险。Windows 暂未接入。

账号目录
01：~/Library/Application Support/Claude（沿用默认账号，不传覆盖参数）
02：~/Library/Application Support/Claude-Second
03～10：~/Library/Application Support/Claude-Profile-03 至 Claude-Profile-10
悬停主按钮可查看完整目录。启动器不会自动删除、迁移或覆盖数据。 删除：点卡片右侧“···”→“删除该实例…”，确认后整个账号目录移到废纸篓（可恢复）。账号 01 不能删除；运行中的账号需先在 Claude 中正常退出（⌘Q）。

登录
从账号卡片“···”选择“登录 / 重新登录保护…”。新建实例时弹出提醒：可“直接创建”（其他 Claude 保持运行，登录后请核对身份），或“进入登录保护”。请保存工作并正常退出其他 Claude 实例，等待其他账号的检查和启动完成，再确认“保护并打开”。不会替你退出、登出或强杀 Claude。
保护期间只允许从启动器打开目标账号，暂不允许新建其他实例或删除受保护账号。请自行登录并核对浏览器及 Claude 中的身份。完成登录或取消浏览器登录流程后，点击“结束登录保护”并确认。正在检查或启动时，需等待操作完成后再结束保护。
保护状态在重开启动器后仍保留。若从 Dock、终端等外部入口打开其他 Claude，启动器会提示停止登录，但无法阻止外部启动或拦截系统回调。未验证两个真实账号登录是否串号。

Code 配置状态
01 显示“Code 默认”，沿用 ~/.claude 等默认用户配置，与普通终端 CLI 共用。
02～10 未运行显示“Code 待启动”；外部启动或旧实例显示“Code 未确认”。保存工作后正常退出该 Claude，再从启动器启动，会指定各自账号目录内的 ClaudeCodeConfig。
“Code 已指定”只说明本次启动器向核实的新进程指定了独立配置，不表示已验证 Code 的实际写入。重开启动器后，已有实例会保守显示“未确认”。不会读取进程环境变量，也不会移动、合并或删除旧记录。两个不同编号仍可能由用户登录同一个真实账号，启动器不读取身份来判断。

后台检查
打开和删除前，后台只检查存储元数据，不读取账号内容。同账号检查期间不能重复操作，其他账号仍可使用。检查完成会重新核对进程、登录保护和路径；原实例若已经退出或被替换，不会自动重启或静默切到新实例。无法识别官方进程时仍暂停全部启动操作，避免重复启动。

项目管理（本机公共入口）
新增“识别并导入”：检查所有已创建的 01～10 账号，包括未运行账号和仍保留在本机的历史记录。识别完成后，核对目录、勾选需要的项目，再点“导入所选”。重复目录不重复添加；已有名称、分组、排序和上次账号保留。取消不会写入清单。
只读取支持格式的目录前缀，不读取后面的正文、凭据或项目文件，不改客户端记录，不启动／退出账号，不联系官方服务。它只汇总启动器的公共入口，不同步 Claude 原生侧边栏、文件或会话。
每个账号会显示识别和跳过结果。未找到不代表没有项目：未知格式、已删除的记录、云端项目、额外工作目录无法完整识别；失效或受保护路径跳过。主目录、根目录和临时目录请手动添加。本机若恰好存在与远程会话相同的路径，请在预览中核对。
左侧“项目管理”→“添加目录”，用系统选择器选已有文件夹，填写名称和分组。清单全局共享，所有账号都能用；不复制目录、不扫描磁盘、不导入 Claude 内部项目或会话，不跨电脑同步。
表格显示名称、分组、路径、状态和上次使用的账号。长文本会省略，悬停可看完整内容；切换到项目页或点击“刷新状态”重新检查目录。状态仅为正常／不存在／无权限，目录失效不会被自动新建或替换。
“···”菜单可修改名称和分组、上移／下移排序、在 Finder 显示、复制路径，或从清单移除。移除只删除入口记录，绝不删除、移动项目文件。
“打开”可选择任意账号，默认选择上次使用的编号，不绑定账号。经过与实例页相同的 PID、登录保护和存储检查后，复制路径、在 Finder 中显示并激活或启动该账号。请在 Claude 中选择此文件夹。不会自动把文件夹交给 Claude，也不会让 Claude 原生侧边栏或会话列表自动一致。
检查失败或取消时，不更新上次账号、不复制路径或显示 Finder。上次账号只表示通过检查后发起过打开操作，不保证 Claude 已打开文件夹；后续若启动失败，请处理账号错误后重试。
同一 macOS 用户下，各账号本来就能访问同一个项目。共享项目中的代码、CLAUDE.md、.claude/settings*.json、.mcp.json 会互相影响，这是便利性与隔离之间的取舍。同一项目请轮流使用；启动器无法检测多个实例同时编辑，也不锁定或合并文件。
不能添加账号数据目录及其子目录、任何 ClaudeCodeConfig、启动器自身的数据目录或应用包。重复真实目录只添加一次，添加主目录或根目录需要确认。启动器不读取项目文件内容，只检查目录是否存在、是否可访问。
清单为 ~/Library/Application Support/Claude Launcher/projects.json，权限 0600，原子保存。损坏的文件会改名为 projects.json.corrupt-随机编号 并保留，界面提示后可重新添加目录；无法保留、权限不安全或来自未来版本时停止写入，原文件不覆盖。

仍共享的资源
目录隔离不能隔离系统权限、应用级加密设施、浏览器回调、日志、用户项目、网络和本地服务。需要工作区隔离时使用各自项目副本及服务端口；选择共享同一个项目则接受代码、项目规则、MCP 配置和本地权限文件相互影响。启动器不自动复制项目或修改这些配置。

窗口恢复
按匹配主进程 PID 激活。恢复最小化窗口可能需要系统辅助功能授权。使用同一固定证书重建可保持签名身份；证书更换或使用 ad-hoc 签名可能需要重新授权。启动器不会修改系统权限。本轮真实窗口恢复未验证。

构建
源码见 src/main.m、src/Projects.m、src/ProjectImport.m 和 scripts/build.sh。在项目根目录运行 SIGN_IDENTITY="ClaudeLauncher Local Signing" /bin/zsh scripts/build.sh，可传入独立验证输出目录。依赖 Xcode Command Line Tools，使用原生 AppKit；本机优先 MacOSX15.4.sdk。
日常打开 /Applications/Claude 启动器.app。本轮开发构建在 build/Claude 启动器.app，未安装到 /Applications。重建不会更换正在运行的启动器进程；测试新版需正常退出旧启动器后打开 build/ 中的应用，这不会退出已有 Claude 实例。旧 Claude 实例要采用新的启动配置，仍需你保存工作后自行正常退出并重新启动。
构建仅为启动器本身固定证书签名，使用 resources/icon/ 中的自有图标，不复制或修改官方 Claude.app。通用二进制支持 Apple Silicon 与 Intel，未做 Apple 公证。
