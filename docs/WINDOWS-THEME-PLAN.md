# Windows 主题实施方案（待确认）

本轮只评估，不实施。默认浅色不变，设置增加跟随系统／浅色／深色，存储 theme=0／1／2（默认 1）。

现状：LauncherUI.cs 的控件、内嵌 XAML、动态图形和插画渐变包含大量直接颜色值，单纯修改窗口背景无法覆盖下拉框、菜单、对话框、提示条及用量进度。

建议实施顺序：
1. 把纸张、卡片、文字、边框、强调色、状态色统一为语义画刷；静态控件用 DynamicResource，运行时创建的控件统一从主题资源取值。保留现有布局。
2. 浅色按当前色值；深色重新校验文字和状态色对比度，插画降至约 30% 不透明度，品牌按钮保持白字可读。避免直接对截图或全部 RGB 值机械反色。
3. 跟随系统只读当前用户 AppsUseLightTheme，并监听系统设置变化；不得写系统主题或权限。监听只更新本地样式，退出时解除。
4. 覆盖五页、六个设置分类、菜单、提示、详情、交接和更新窗口；检查禁用、悬停、选中、焦点与滚动状态。
5. 三主题分别生成离屏预览；测试保存、导入、默认值和切换。真实 Windows 高 DPI、系统主题切换、键盘导航及高对比度另做 GUI 验收。

工作量判断：中到大，需要先统一颜色来源，再做全界面回归，适合独立变更。用户确认此方案后再开发；本轮不发布主题功能。
