# Windows 1.9.4

修复账号启动时报“账号存储隔离检查未通过：仅支持普通符号链接。”

- 原因：账号 Code 配置的 `skills` 里有用目录联接（`mklink /J`，不需要开发者模式）装的 skill，指向 `~/.claude/skills`。启动器之前只认符号链接，联接一律报错，而且提示里没有路径。
- 现在：配置同步白名单位置（顶层 `settings.json`、`*.md`，`skills`、`agents`、`commands`、`output-styles` 的直接子项）上的目录联接，和符号链接走同一套检查：目标不能是账号数据、启动器数据、`~/.claude.json` 或它们的上级，目标内容要属于本人、没有不允许的硬链接、不超大小上限。联接只接受盘符路径，卷挂载点拒绝。其他存储位置的联接仍然拒绝。
- 链接检查未通过时，提示里写出是哪个路径。

不新增 Claude／Anthropic 访问，不新增网络入口；只读文件元数据和链接目标，不打开 Claude 数据内容。程序和安装包仍未代码签名（Authenticode）。macOS 不涉及。

未验证：安装后用真实账号点击启动（已用新程序只读核对账号 02 的 4 个真实联接均放行；完整目录检查在开发终端受 Claude 桌面版沙箱限制未跑完）。
