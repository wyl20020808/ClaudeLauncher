# 跨平台行为规格

## [Windows] 1.7.17 交接同步补充（2026-10-30，开发版未发布）

本节覆盖下方 Windows 历史段落中尚未实现或仍为草稿的描述；六批结果和平台差异见 [接手回执](HANDOFF-windows-1.7.17-response.md)。

- 账号操作的占用从存储检查保持到最终扫描及启动／激活交接结束，所有退出分支通过 finally 释放；同账号重复操作拒绝。异步扫描只应用最新发起代次的结果，旧失败不覆盖新成功。
- 更新每次开始／取消递增代次，旧下载进度、完成、失败及结束回调不能改变新任务；安装包校验完成和延迟安装前再次核对。取消只清理本任务临时包。Setup 重开失败提示本地恢复路径，不声称安装后的运行状态健康。
- 设置、日志及诊断写入锁定目录链并拒绝重解析点；现有文件必须为当前用户或令牌默认所有者的单链接普通文件。通用写入上限 16 MiB，设置读取上限 64 KiB，诊断单文件达到 1 MiB 后截断轮换。写入失败提示；日志清空先写空列表成功再清内存。诊断失败提示不再写日志，避免递归。
- 用量趋势只接收合并旧缓存前的新鲜读取结果，独立保存于 `settings.json.usageTrend`，保留 8 天、最多 4000 点、相同数值 15 分钟内去重；显示近 7 天图及重置分段估算，建议已观察周用量最低的已有账号。关闭本地用量显示清空趋势。无新增读取或网络请求。
- 项目使用 `%LOCALAPPDATA%\Claude-MultiLauncher\projects.json`，采用本规格 version 1 格式；兼容旧 `settings.json.projects`，保留旧文件。支持名称、分组、排序、复制路径／资源管理器、用账号打开和本地交接；损坏清单改名保留，未知版本停止写入。最多 500 项。路径拒绝账号／配置／启动器数据与安装目录、UNC、网络盘及目录链重解析点；主目录和盘符根额外确认。[Windows 差异] 对链接别名直接拒绝，不跟随解析。
- 识别并导入仅扫描固定账号候选路径的 `claude-code-sessions` 三层结构，逐字节读批准前缀；确认的 Windows 4.4212.0.0 顺序为 sessionId、可选 cliSessionId、cwd、originCwd，之后立即停止。上限 20000 个目录项／5000 记录／32768 字节前缀，拒绝不安全所有者、链接、硬链接、其他用户可写源和未知格式。达到上限明确报告；导入前再次校验路径。Windows 原生侧栏写入不在本轮实现内，必须单独授权实验。
- 账号配置同步使用同一白名单、凭据键拒绝、50 MiB／5000 条目限制、逐项预览、默认只补缺、覆盖前送入回收站、同目录临时项及不覆盖移动。[Windows 差异] 默认请求符号链接，能力探测失败自动退回拷贝，不提权、不改开发者模式；来源已有符号链接只复制链接、不跟随读取，系统不允许复制链接则停止提示。来源 settings.json 本身为链接时拒绝。Code 配置白名单内的共享链接通过目标元数据检查后允许启动；其他官方存储继续拒绝链接。
- 主题 `theme=0/1/2` 对应系统／浅／深（默认浅），画刷即时更新；系统模式只读并监听系统外观。语言 `language=0/1` 对应中文／English（默认中文），复用 `resources/i18n/english.strings`，缺词回退中文。单次运行语言固定，保存变化后可明确选择重新打开启动器；只等待本启动器原 PID 退出，不操作 Claude。交接规则和指令随界面语言。
- 登录启动为直接开关，注册失败恢复实际状态，仍拒绝开发路径注册。前台 Ctrl+1～0 及可选全局 Ctrl+Alt+1～0 保持原检查流程。
- 发布后复核明确区分下载失败（待复核、保留发布）和成功下载后的内容不符（回滚），用离线替身测试；未运行真实发布或更新网络流程。

## 本地安全与可操作界面（2026-10-28，macOS feature/local-settings）

本节优先于下方旧版本更新描述。产品核心规则：管理器不向 Claude、Anthropic 或其 Cloud、API、遥测、登录服务发请求，不读取凭据，不通过 CLI、浏览器或官方界面刷新间接查询。设置不改变 Claude 的登录、会话、目录或运行状态。用户主动使用既有启动／激活功能时，官方客户端自身的正常联网不由管理器控制。规则写入根目录 AGENTS.md，后续两端开发均须遵循；本轮实现和验证仅覆盖 macOS；Windows 的网络边界于 2026-10-29 在 feature/windows-update-boundary 对齐（见下文「网络边界」中的 [Windows]），系统设置与账号／日志交互待后续分支。

### 系统设置

六个分类均可操作；控件使用 AppKit 原生目标／动作，保留水墨视觉。没有保存／撤销按钮：每次切换或选择立即写入启动器自己的 `NSUserDefaults` 中 `localSettings` 并生效（2026-10-29 用户要求）；被拒绝（如更新进行中改联网开关）或写入失败时弹出提示，控件回到已保存值。「恢复默认…」确认后立即保存默认值。类型和可选值按白名单校验，异常值回落默认，不接受任意路径／命令／地址。

| 分类 | 行为 |
|---|---|
| 常规设置 | 关闭窗口继续运行（默认开）、菜单栏图标（默认开）、辅助功能状态与系统设置入口。关闭继续运行后，最后一个窗口关闭即退出启动器，Claude 仍运行。 |
| 启动行为 | macOS 13+ 通过 SMAppService 管理本启动器登录项，设置页用开关直接切换、立即生效（不再弹确认框）；仅接受标准应用程序安装路径，开发副本拒绝注册。macOS 12 提供用户与群组设置入口。恢复上次启动器页面（默认关）、默认页面（实例管理）、本地进程刷新间隔（1／3／5 秒，默认 1 秒）、点击指定账号时恢复最小化窗口（默认开）。全局快捷键 ⌃⌥1～⌃⌥0（`globalHotkeys`，默认关，Carbon 热键，不需辅助功能权限；被占用的组合跳过并记日志），效果与点击对应账号相同；未创建的账号只提示不创建，新启动前先显示启动器窗口以便看到检测对话框。启动器在前台时“账号”菜单 ⌘1～⌘9、⌘0 打开已有账号（“显示账号窗口”不再占用 ⌘0）。菜单栏账号项在开启全局快捷键时显示对应组合。绝不自动启动／恢复 Claude。 |
| 外观设置 | 显示水墨插画（默认开）、显示本地界面用量（默认开）。关闭用量显示后停止后续界面读取与通知监听、清空显示缓存；已在进行的只读任务可完成，但结果被丢弃。主题（`theme`：0 跟随系统／1 浅色水墨（默认）／2 深色水墨），通过 `NSApp.appearance` 生效；深色时调色板按色相保持、明度翻转生成，插画以 30% 不透明度绘制，品牌填充色保持深色以保证白字对比度。界面语言（`language`：0 简体中文（默认）／1 English，macOS 已实现，Windows 待实现）：英文文本集中在 `resources/i18n/english.strings`（键为中文原文，格式占位符须一致，缺失时回退中文）；界面在一次运行内固定，切换后提示“立即重新打开”只重启本启动器，不影响 Claude。日志级别与实例按固定中文代码保存、显示时翻译；写入 CLAUDE.md 的交接规则和复制的交接指令随界面语言。不提供浏览器选项。 |
| 数据与存储 | 显示／复制启动器数据目录，导出已保存偏好为 version 1 JSON；导入同格式文件（≤64 KB，`version` 必须为 1），逐项按白名单校验，无效或未知项保持当前值，先列出变更（含联网开关）由用户确认后立即保存；启动器日志上限 100／500／1000（默认 500）。不导出账号、别名、项目、凭据。恢复默认经确认后立即保存并生效，不清除别名、项目、登录保护、登录项或任何 Claude 数据。 |
| 消息通知 | 启动器窗口内警告提示（默认开）、系统提示音（默认关）、按已保存设置测试。用量提醒（`usageAlert`：关闭／70／80（默认）／90%）：某账号当前读取到的五小时已用比例达到阈值时，在状态栏、日志与窗口内提示中说明，并推荐其他可打开账号中观察到五小时用量最低且低于阈值的账号（含“上次记录”），实例页显示“切换到账号 NN”按钮。提醒状态存在启动器偏好 `usageAlertState`（`{账号: 提醒时的重置说明}`）：同一重置说明在未观察到低于阈值前不再提醒（重启后仍然有效）；观察到低于阈值即重新启用，因此跨周出现相同的“周几 时刻”文本也会再次提醒；重置说明变化也会提醒。提醒文本、状态栏与日志只用账号编号，不写 Code 用户名或别名。只用已观察数据，不额外读取或查询。不开启推送，不读取 Claude 消息。安全确认与错误弹窗不受通知开关控制。 |
| 关于软件 | 版本、离线使用帮助、复制基础诊断（仅版本／系统版本／辅助功能状态／联网开关）、手动更新开关与检查按钮。 |

不再提供自动恢复 Claude 实例、改默认浏览器、迁移账号目录或未存在的批量启动间隔。默认页面只在「恢复上次页面」关闭时可选。设置保存不修改运行中 Claude 的配置。

macOS 日志存储：启动时和读写前逐级检查启动器数据目录及上级，拒绝符号链接；通过不跟随链接的目录／文件句柄访问。日志必须为当前用户所有的普通文件、链接数为 1、大小不超过 16 MiB，写入以 0600 权限原子替换。不安全或不可访问的日志不读不写，日志页显示存储不可用，状态栏每次运行只提示一次，不递归记录失败。追加保存失败时保留内存记录（仍遵循条数上限）；清空先把空列表写入磁盘，成功后才清内存，失败则保留原列表。数据目录本身无法安全打开时，在建立实例锁前提示并停止启动。

**[Windows]**（2026-10-29，feature/windows-settings）同一六分类，设置更改即时保存并生效，WPF 原生控件（开关为带切换状态的复选框，选项为下拉框）。布局对应 macOS 1.7.14（feature/windows-settings-layout）：顶部分段标签（常规／启动行为／外观／数据与存储／通知／关于）切换分类；各分类按小标题分组为白色圆角卡片，每行 60 px，左侧图标、标题与说明，右侧开关／下拉／按钮／只读值；分组后可有带信息图标的提示框；内容超出时在面板内纵向滚动。没有保存／撤销按钮和退出前未保存提示；恢复默认确认后立即保存。更新期间修改联网开关被拒绝或写入失败时弹窗提示，控件回到已保存值。

- 存储：`%LOCALAPPDATA%\Claude-MultiLauncher\settings.json`，`{"version":1,"closeToBackground":true,"showTray":true,"rememberPage":false,"startPage":"instances","refreshInterval":3,"restoreMinimized":true,"showArtwork":true,"showUsage":true,"logLimit":500,"localNotifications":true,"notificationSound":false,"allowUpdates":false}`。逐项按类型与可选值校验，单项异常只回落该项；文件缺失、损坏或版本不是 1 时全部用默认。同目录临时文件写完后替换；保存失败保留原文件，控件恢复已保存值。`startPage` 存页面名（`instances`／`accounts`／`logs`／`settings`／`projects`），不存序号。上次页面只在开启「恢复上次页面」时写入同目录 `last-page`。
- 常规：关闭窗口继续运行（开：隐藏窗口，托盘或再次打开启动器可恢复；关：关闭窗口即退出启动器，Claude 继续运行）；通知区域图标（关闭后托盘菜单不可用，再次打开启动器即可显示窗口）。
- 启动行为：开机启动写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `ClaudeMultiLauncher` 值（带引号的程序路径），单独确认、立即生效、不进草稿；只在程序位于 `%LOCALAPPDATA%\Programs\Claude 多开启动器\ClaudeLauncher.exe` 时允许开启，开发副本拒绝；关闭只删除本值且仅当它指向本启动器。卸载程序不处理该值（升级时 Setup 会先运行旧卸载程序，处理它会丢失用户选择），卸载前请先关闭开机启动。**[Windows 差异]** 本地进程刷新间隔默认 3 秒（实测一次 WMI 扫描约 280 ms，1 秒间隔开销过大），可选 1／3／5 秒。点击账号时恢复最小化窗口：关闭时若目标窗口已最小化，不还原、不切换，只提示从任务栏打开。
- 外观：显示水墨插画（侧栏山水、主区背景、账号卡片插画）；显示本地界面用量（默认开，`showUsage`，行为见「本地界面用量」[Windows]）。主题可选；界面语言见上方外观设置（Windows 待实现）。
- 数据与存储：在资源管理器中显示、复制启动器数据目录；导出已保存设置为 `{"version":1,"settings":{…}}`（不含账号、别名、项目、凭据、登录保护、上次页面）；启动器日志上限 100／500／1000（默认 500），保存后立即截断内存与日志文件。
- 消息通知：窗口内提示为主区底部的临时提示条（约 5 秒），用于警告与错误；提示音用系统“感叹号”声音，仅在窗口内提示开启时生效；测试按钮按已保存设置显示。安全确认与错误弹窗不受影响。
- 关于软件：版本、离线帮助、复制基础诊断（仅启动器版本、Windows 版本、联网更新开关、Claude/Anthropic 请求禁止）、更新开关与检查按钮。

### 账号与日志交互

- 账号搜索支持本地别名、固定编号和目录；状态筛选支持运行中／未运行／处理中／异常。进程扫描失败时显示未知，不伪装成确定状态。统计仍按全部已有账号计算。
- 铅笔按钮设置最多 24 字的本地别名，去除首尾空白，拒绝控制字符；留空恢复默认。仅写 `accountDisplayNames`，不更改邮箱、身份或目录。实例卡片与账号表同步显示，编号始终保留。
- 默认名称（2026-10-29 用户要求）：无别名时显示本地 Claude Code 配置中的用户名，01 读 `~/.claude.json`（与终端 CLI 共用，可能不同于桌面端登录），02～10 读 `<数据目录>/ClaudeCodeConfig/.claude.json`；只取 `oauthAccount.displayName`，按别名规则校验，仅缓存在内存、按文件修改时间重读，不保存、不记录日志、不导出。文件须为本人所有的普通文件（非链接、≤32 MB）。纯本地读取，不发网络请求、不启动 CLI、不访问钥匙串或 `config.json`；取不到时显示“账号 NN”。离屏截图和 UI 自检不读取真实文件。
- **[macOS]** 账号表（2026-10-29 用户要求）：列为账号名称、Code 用户名、状态、最近使用、操作。“Code 用户名”显示上条同一来源的 `oauthAccount.displayName`（取不到为“—”，悬停说明可能不同于桌面端登录），替代原先固定写“不读取”的登录身份列；去掉与编号重复的“对应实例”列。每行有与实例卡片同一流程、同一标题和启停状态的“创建／启动／打开”按钮（存储检查、网络环境检测、登录保护均相同）。
- **[macOS]** 最近使用：启动器成功启动（LaunchServices 无错误返回）或按 PID 激活某账号时，把当前时间写入启动器自己的 `accountLastUsed` 偏好（键 1～10，值为日期，读写时丢弃非法项和超过当前 1 天的未来时间）；无记录时退回账号目录修改时间并在悬停中注明为近似值。不读取 Claude 数据，恢复默认设置不清除。
- **[macOS]** 排序：按编号（默认）／按最近使用（新在前，无时间的排后）／按状态（异常、未知、处理中、运行中、未运行），同组按编号；选择保存在 `accountSort` 偏好。
- **[macOS]** “···”菜单新增“查看账号详情…”：名称、Code 用户名、目录、状态、主进程 PID、Code 配置状态、最近由启动器打开时间、登录保护、最近错误；目录大小在后台按文件属性累加（不跟随符号链接、不打开文件），关闭对话框即停止，结果不保存。可从对话框在 Finder 中显示目录。Windows 尚未实现以上四项。
- 实例卡片只显示名称（上）和运行状态（左下），不再显示目录与 Code 配置标签；Code 配置状态和目录改在卡片悬停提示中显示。
- 原生复选框支持全选当前结果和部分选中；「复制选中路径」只复制当前可见选择。筛选隐藏的选择会清除，避免误操作。没有批量删除或自动批量启动。
- 日志支持最近 7 天（默认）／最近 24 小时／最近 1 小时／最近 5 分钟／本次运行／全部时间、实例、级别、全文搜索的组合筛选；每页 10 条，数字页码（首页、末页、当前页前后各一页，中间省略）与上一页／下一页根据结果启停。级别以信息／警告／错误色块显示。空结果有说明。全文可选择复制，截断单元格有完整提示。
- 导出写出全部筛选结果，非仅当前页；清空需确认，只清启动器自己的日志文件。日志保存在 `~/Library/Application Support/Claude Launcher/launcher-log.json`（权限 0600，最新在前），重启和软件更新后保留；按设置限制数量，超出删除最旧记录；损坏或格式不符的记录在读取时丢弃。确认弹窗与文件选择由用户决定。

**[Windows]**（2026-10-29，feature/windows-accounts-logs）同一规则，WPF 原生控件：

### Code 配置状态（两端）

- 01 显示“Code 默认”，仍与普通终端 Claude Code CLI 共用默认用户配置。
- 02～10 未运行显示“Code 待启动”；已运行但启动来源未确认显示“Code 未确认”。已有目录、正在运行和旧版启动记录均不能证明独立配置已生效。
- 仅本次启动器通过 LaunchServices 指定 `CLAUDE_CONFIG_DIR`，返回一个启动时间不早于请求时间、且主程序路径和账号参数匹配的新进程时，记录该进程对象。后续扫描仍为同一存活进程才显示“Code 已指定”。这仅表示启动参数已指定，不能宣称 Code 实际存储已验证。
  - **[Windows 差异]** 以 `Process.Start` 返回的 PID 记录，扫描到该账号唯一主进程为同一 PID、且 WMI `CreationDate` 不早于请求时间才显示“Code 已指定”；进程退出、PID 变化或重复主进程后清除记录。官方程序若转交给其他进程，PID 不匹配，保守显示“Code 未确认”。
- 不读取进程环境变量；记录仅在内存中保留。启动器重启、目标退出、PID 改变或重复主进程时，不能继续沿用已指定状态。旧实例由用户保存工作并正常退出后重新启动，不自动重启，不迁移旧配置或历史记录。

### 登录保护（两端）

- “···”菜单提供“登录 / 重新登录保护…”。首次创建账号空间时弹出提醒，用户选择“直接创建”或“进入登录保护”，不强制保护。
- 进入前与确认后重新扫描：其他管理/未管理的官方主进程、目标重复主进程、其他账号正在检查或启动、任何扫描错误都阻止进入。不会退出、登出或强杀任何实例。
- 保护账号编号保存在启动器自身偏好中，重开启动器仍保留。保护期间不允许通过启动器打开其他账号、新建实例或删除受保护账号；目标检查和启动仍可正常完成。
- 用户自行完成登录或取消浏览器登录流程，再确认“结束保护”。存在检查或启动操作时暂不允许结束，避免后台操作跨越保护状态。
- 保护不截获回调、不读取身份，不能约束 Dock、终端等外部启动。发现外部实例时持续提示停止登录；不能保证回调一定属于目标账号。
  - **[Windows 差异]** 保护编号保存在 `%LOCALAPPDATA%\Claude-MultiLauncher\login-protection`；外部入口为开始菜单、任务栏、终端等。

## 进程识别

- 只认官方主程序路径；排除 Helper、GPU、renderer（参数含 `--type`）以及 Claude Code CLI。
- 从系统读取命令行参数解析 `--user-data-dir`（支持 `=` 与空格两种形式）：无参数为 01；重复参数、相对路径或缺值视为无法识别并暂停操作；不在 01～10 内的目录记为未管理实例。
- 不读取进程环境变量（可能含凭据）。
- 任何官方实例无法核对参数时，暂停启动，不重复启动、不结束进程。

## 启动与激活

- 运行中：按 PID 激活。激活前再次核对该 PID 的路径和账号；不以按程序名打开代替。
  - **[Windows 例外，已确认]** 主进程在托盘中、按 PID 找不到可见窗口时，允许用同一 `--user-data-dir` 再启动一次，由 Claude 单实例锁（4.29 含 `requestSingleInstanceLock`，按 userData 区分）转交已有进程显示窗口。必须同时满足：该账号恰好一个已核实主进程且无可见窗口；使用该 PID 的可执行文件；之后重新扫描，若同账号出现第二个主进程则报错，不结束任何进程。macOS 保持纯 PID 激活，最小化窗口经辅助功能恢复。
- 同一账号多个主进程：报错，不激活、不结束任何实例。
- 未运行：校验存储后以新实例启动；启动中禁用按钮防重入，35 秒未出现主进程报失败。
- 网络环境检测（2026-10-29 用户要求，两端）：每次启动新实例前（激活已运行实例不检测），后台检测本机代理环境，状态栏显示“正在检测电脑网络环境…”，然后弹窗列出结果，用户点“确认启动”才启动，“取消”不启动；检测与对话框期间占用该编号。确认后重新扫描并核对保护／进程状态再启动。
  - 只做本地检测（用户选择，不新增网络入口）：读系统代理（macOS `SCDynamicStoreCopyProxies` 的 HTTP／HTTPS／SOCKS／PAC；Windows HKCU `Internet Settings` 的 `ProxyEnable`／`ProxyServer`／`AutoConfigURL`），以及 TUN／VPN（macOS 主网络接口为 `utun`／`tun`／`tap`／`ppp`／`ipsec`；Windows 已启用、有 IPv4 的 PPP 网卡或名称／描述含 Wintun、TAP-Windows、WireGuard、Clash、Mihomo、sing-box、tun、vpn 的网卡，排除系统 Tunnel 类型）。
  - 代理地址为本机回环（`127.*`、`localhost`、`::1`）时 TCP 连接实际配置的回环地址与端口（`localhost` 按 127.0.0.1；Windows 先严格解析 IP 再校验为回环）（超时 0.8 秒）判断代理软件是否在运行；非本机地址不连接，只显示“未探测”。不下载 PAC，不查询公网 IP 或所在地区。
  - 结论：任一 TUN／PAC／非本机代理／可连接的本机代理为“已检测到代理”；否则为“未检测到可用代理”并建议先开启系统代理或 TUN。两种结论都允许用户确认后继续启动。
  - 未检测到可用代理时按钮为“取消”（默认，回车即取消）／“仍然启动”，须明确点击才启动（两端）。
  - **[macOS]** 同时列出正在运行的常见代理软件（按 bundle 标识前缀与名称关键词识别，如 Clash Verge、ClashX、Surge、Shadowrocket、V2rayU、Stash、Quantumult X、FlClash、Mihomo Party、sing-box），只读取应用名称与标识；有代理软件运行但无可用代理时提示在该软件中开启系统代理或 TUN。Windows 未实现该项。
  - macOS `--proxy-check` 输出同一检测结果（本地，不联网）。
- 启动器单实例；再次打开时唤起已有窗口。关闭启动器不退出 Claude。
- 递归存储检查放到后台，不占用界面主线程；同账号检查期间禁止重复打开/删除。不同账号可独立检查，失败只记录在该账号。完成后重新扫描进程、检查保护状态及根目录元数据。原本要激活的 PID 若退出或被替换，不自动重启，也不静默切换到另一个 PID。删除同样在后台检查完成后再扫描和校验路径。
- **[macOS]** LaunchServices 请求超过 35 秒仍未回调时报告超时，但继续保留该账号的启动中状态，禁止重试及其他账号进入登录保护，直到系统返回。不会强制结束启动请求或 Claude。
  - **[Windows 差异]** `Process.Start` 为同步调用，立即返回 PID 或失败，不存在悬挂的启动请求；35 秒超时只用于等待主进程窗口出现。
- 无法识别的官方进程仍触发全局暂停；这是防止重复启动的保护，不因降低耦合而取消。

## 存储校验

只检查元数据，从不读取内容。目录及各级上级不得为链接或非目录；以下存储项不得为链接、非本人所有、普通文件硬链接：
`Cookies`、`Cookies-journal`、`Network`、`Local Storage`、`Session Storage`、`IndexedDB`、`Partitions`、`Local State`、`Preferences`、`config.json`、`Cache`、`Code Cache`、`Service Worker`、`ClaudeCodeConfig`。

配置同步链接例外（2026-10-30，修复链接模式导致 02～10 无法启动）：`ClaudeCodeConfig` 内只有配置同步可放置的条目（顶层 `settings.json`、顶层 `*.md`，`skills`、`agents`、`commands`、`output-styles` 的直接子项，不含点开头的名称）可以是符号链接。链接目标解析后须由当前用户所有（目标不存在时跳过所有者判断），不得是 `~/.claude.json`、启动器数据目录，也不得位于账号数据目录或 `~/.claude` 内的白名单条目之外，不得是这些目录的上级。`ClaudeCodeConfig` 或分类目录本身是链接、其他位置的链接仍判为未通过。只看链接元数据，不打开目标内容。[Windows 待同步] 按本段补齐 `~/.claude.json`、`~/.claude` 非白名单条目及上级目录的目标判定。

未通过时的处理（2026-10-30 用户决定：本地风险警告，不阻止启动）：

- 启动或打开账号：弹警告列出原因和可能的影响，按钮为“取消”（默认，回车即取消）和“仍然继续”。选择继续后，本次启动不再因隔离检查中止（含启动前复核和创建目录后的复核）；下次点击重新检查、重新警告，不记住选择。取消时账号保留错误状态，不启动。启动器不修改、不修复这些文件。
- 仍然阻止：删除账号（路径异常时绝不移动数据）、登记项目到账号（会写账号数据）。账号路径已存在但不是目录时无法启动，也仍然阻止。
- 网络环境检测不受本段影响，见「启动与激活」。
- [Windows 待同步] 当前仍直接阻止启动。

Windows 对应：重解析点（符号链接、junction）等同链接；硬链接数通过文件信息查询。所有者按 ACL 所有者 SID 判断：接受当前用户，或启动器自身令牌的默认所有者（启动器以管理员运行或关闭 UAC 时为 Administrators 组，与其自建目录一致）；其他所有者拒绝。

## 项目清单

先在 macOS 实现，Windows 端以后按同一规格实现。项目目录本来就由同一 macOS 用户下的所有账号共享；公共清单只是统一入口，不复制、不同步、不合并任何项目内容或会话。清单只存在本机，不跨电脑同步。可选的原生侧栏目录登记见下文，独立于只读识别与公共清单导入。

### 共享的取舍

- 所有账号引用同一个真实目录，因此项目中的代码、文档、`CLAUDE.md`、`.claude/settings*.json`、`.mcp.json` 都会被使用该项目的账号共同读写。项目级配置共享与“账号尽量隔离”方向相反，这是用户为了方便主动选择的取舍；账号登录、内部会话和用户配置目录仍独立。
- 同一项目请轮流使用。启动器无法检测多个实例同时编辑，也不提供文件锁、冲突检测或合并。

### 界面与操作

- 左侧新增“项目管理”，顺序为实例管理、账号管理、项目管理、日志记录、系统设置。沿用表格样式，列为名称、分组、路径、状态（正常／不存在／无权限）、上次使用账号、操作。
- 清单全局共享，不建立账号与项目绑定。任何账号均可打开任何项目，只记录上次使用的账号编号作为下次选择的默认值；未使用时为空。
- 保留通过 `NSOpenPanel` 选择已有文件夹；支持修改名称、分组、上移／下移排序、在 Finder 显示、复制路径和移除记录。移除绝不删除或移动实际目录及文件。
- “用账号打开”选择账号后复用 `selectAccount` 的完整流程（PID 核对、登录保护、后台存储检查及启动防重入）。通过检查并请求激活／启动目标账号时，复制项目路径到剪贴板、在 Finder 显示目录，提示“请在 Claude 中选择此文件夹”。记录的是最近通过检查并发起的账号操作，不代表 Claude 已加载项目。检查失败或用户取消时不更新此记录、不执行路径交接。
- 不使用 `claude://`、不使用 `open -a` 打开文件夹，不改账号数据。官方 4.29 的只读调查未发现“打开文件夹到指定实例”的可靠入口，`claude://` 可能交给任意实例，因此实际选取目录由用户完成。

### 本地交接（macOS，2026-10-29 用户要求）

用于同一项目在账号之间接力：交接内容只存在项目目录的 `HANDOFF.md`。**启动器不代发、不输入、不点击任何消息**（用户曾提出由脚本在客户端自动发送，因违反“不得通过官方界面间接触发查询”及无人值守切换账号的风险，用户选择本方案）。

- 项目“···”菜单：
  - “写入交接规则到 CLAUDE.md…”：确认对话框显示完整内容后，只在项目根目录 `CLAUDE.md` 末尾追加带 `<!-- claude-launcher:handoff -->` 标记的规则（不存在则以 0644 创建），要求 AI 在阶段完成、重要决定或会话将结束时更新 `HANDOFF.md`，新会话先读它。已含标记则跳过；`CLAUDE.md` 为符号链接、硬链接（链接数不为 1，追加会改动项目外的同一文件）、非普通文件、非本人所有、超过 1 MB、非 UTF-8 或检查后发生变化时拒绝，不改动已有内容（`O_APPEND|O_NOFOLLOW`，写后 fsync）。这是启动器唯一写入项目内容的操作，读取 `CLAUDE.md` 仅为检查标记。
  - “复制‘写交接文档’指令”：复制一段让 AI 写／更新 `HANDOFF.md` 的指令，由用户在原会话粘贴发送。
  - “交接给其他账号…”：沿用“打开”流程（账号检查、网络环境检测、记录上次账号、在 Finder 中显示项目），默认选中上次账号以外、观察到五小时用量最低的已有账号；剪贴板写入含项目路径、要求先读 `HANDOFF.md` 并复述下一步的接手指令。项目没有 `HANDOFF.md` 时先提示，可复制写交接指令、仍然交接或取消。
- 项目行在名称下显示“交接 N 分钟前”（`HANDOFF.md` 的 `lstat` 修改时间，非普通文件不显示，不读内容）。
- 用量提醒：触发提醒的账号若是某项目的上次账号，提示中附带该项目交接文档的更新时间，或提示先写交接文档。
- Windows 本地交接实现与边界见文末「[Windows] macOS 1.7.16 功能同步」。

### 一键识别与导入（macOS）

- “识别并导入”检查全部已创建的 01～10 账号空间，包括未运行的账号。读取范围固定为各账号的 `claude-code-sessions/<账号 UUID>/<组织 UUID>/local_<UUID>.json`，包括仍保留在本机的历史／归档记录；不递归扫描磁盘，不要求 Claude 正在运行。
- 依据官方 4.29 的序列化格式，只逐字节读取记录开头的 `sessionId`、可选 `cliSessionId`、`cwd`、`originCwd` 字符串；优先使用非空 `originCwd`。读完立即停止，绝不预读后面的会话正文、配置或凭据。键顺序／类型不匹配就跳过；不打开其他 JSON、JSONL、浏览器数据库、CLI 配置或日志。不会复制、修改或写回任何客户端记录。
- 这是目录候选识别，不是官方项目清单接口，不能保证历史项目完整。已删除记录、旧／未知格式、额外工作目录、云端项目及没有目录记录的项目不在覆盖范围。路径字段也不能证明记录来自本地会话：本机恰好存在同名远程路径时，需用户在预览中核对。不会自动将工作目录推断成仓库根目录。
- 目录逐层以 `openat` 和 `O_NOFOLLOW` 打开，拒绝链接、非当前用户的源目录／文件、硬链接源文件和可被其他用户写入的源。固定三层枚举，最多检查 20000 个目录项／5000 份记录，单份前缀最多 32768 字节；达到上限明确报告，不能宣称全部完成。
- 后台识别完成后显示可勾选的候选目录、来源账号及逐账号结果。先复用已有路径准入检查，再按真实目录身份去重。已存在项目保留名称、分组、顺序和上次账号；新增项追加到末尾，上次账号为空。主目录、根目录和系统临时目录不批量导入，需走原来的手动添加流程。
- 确认导入时再次校验路径和重复情况，批量原子保存；取消不写入。缺失／无权限／受保护路径、格式不支持、读取失败分别计数；没有候选只表示此次没有识别到，不表示没有项目。清单容量不足或保存失败时整批不写入。
- 全过程仅在本机执行，不请求 Claude 官方接口，不启动、退出或激活客户端，不操作剪贴板／Finder，不改变隔离机制。这里的“同步”仅指向启动器公共清单汇总目录入口，不同步文件、会话或 Claude 原生侧边栏。

### 原生侧栏目标与探索记录

用户追加的目标是：汇总全部已创建账号的本地项目目录后，让未使用过这些目录的账号，也能在 Claude 自身左侧看到对应入口，并在该目录中新建自己的独立对话。这与已发布的“导入启动器公共清单”不同；现有导入功能继续保留。

- 只允许本机目录登记，不调用 Claude 云端项目／会话接口，不同步会话、消息、账号身份、登录状态、环境变量或权限配置。
- 验收必须在目标客户端实际看到入口，并确认新对话草稿指向正确目录。写入配置成功、启动器显示成功、Claude 的环境选择器显示成功，都不能替代原生侧栏验收。
- Claude 4.29.0 第一阶段 GUI 验证未通过上述目标：保存本地环境、开启空分组、切换为按环境分组，都没有为从未创建会话的测试目录生成侧栏入口。对应文件与缓存机制见 [本地侧栏调查](SIDEBAR-LOCAL-RESEARCH.md)。
- 不复制数据库或修改官方应用；未通过实际验收的路径不能宣称已完成。用户授权空归档记录实验及后续接入的具体边界见下文。

用户随后授权受控验证“去掉会话内容后能否保留目录分组”。验证必须从目录路径白名单重新生成记录，不能先复制真实会话再删字段。每个目标使用全新 `local_<UUID>`，仅保留 `sessionId`、`cwd`、`originCwd`、测试标题、新时间戳和 `isArchived`；不带任何 CLI／历史／云端 ID、恢复任务、消息、MCP、环境、权限或账号字段。先用合成数据离线验证，再在用户已正常退出的单一目标账号中独占新建一条测试记录，不覆盖任何现有文件；真实 GUI 验证与离线检查分开报告，验证后清理。此项为第一阶段只读调查之后的明确实验授权；该实验本身不代表批量功能已交付。

第二阶段实验结果：在 Claude 4.29.0 中，`isArchived=true` 的全新空记录配合“显示空分组”，可以生成原生侧栏目录入口，显示“无活跃会话”；正常重启后保留。点击新建会话能准确进入该目录的信任确认；该次实验取消确认，没有授予目录信任或发送消息。删除唯一实验记录并重启后，分组消失。此方案需要长期保留空归档记录，不能把记录文件全部删除后仍宣称目录已登记；详情见调查报告的第二阶段。该阶段尚未实现批量应用与去重；后续产品接入及真实目录验收见下节。撤销、升级兼容和长期清理策略仍未完成。

### 同步会话（macOS，2026-10-30 用户要求）

把一个账号的本地 Code 会话，以清理副本的形式放到另一个账号的同一项目下，让目标账号继续工作。这是单向、一次性的独立副本：两边之后各自发展，不合并；再次同步生成新副本，不覆盖旧副本。本节是上文“不同步会话”及“不打开 JSONL”的唯一例外，仅由用户点击触发。

- 入口：项目页“同步会话…”。列出公共清单中状态正常的项目下，各账号的本地会话（`<配置目录>/projects/<目录名>/<UUID>.jsonl`），只读文件末尾 256 KiB 取标题。选择会话和目标账号；运行中或与来源相同的账号不可选。来源账号是否运行不影响，读取期间文件变化则报错，请稍后重试。
- 清理：从白名单重新生成，不复制后删字段。沿 `parentUuid`（压缩边界用 `logicalParentUuid`）从最后一条用户／助手消息回溯当前主链；废弃分支和子代理不带。保留用户和助手文字及排队的用户指令；工具调用转成一行 `[历史工具请求：工具名，项目内相对路径]`（项目外路径省略，不带命令和参数）；工具结果、思考块、图片、压缩摘要、元信息消息和注入标签全部丢弃。连续同角色消息合并。第一条消息前加说明，告知这是清理副本，改动以磁盘和 git 为准。
- 脱敏：邮箱、常见 API Key、Bearer 令牌和项目外的主目录路径按规则替换。规则无法识别所有秘密，因此必须预览。
- 工作目录：主链第一个 `cwd` 须与所选项目是同一真实目录；后续 `cwd` 须在其内，切换时在文字中标注，超出则拒绝。目录名转换后超过 200 字符时拒绝。
- 预览：写入前显示清理报告和将写入的全部文字；超过 100 KB 时提示，不自动截断。
- 写入：`RegistrationGuard` 全部校验外，只允许 Claude 4.4212.0（已验证版本）。目标须有唯一安全的账号／组织目录。先发布 JSONL，再发布记录，都用临时文件和 `RENAME_EXCL`，权限 0600；记录失败时只删除本次新建的 JSONL。JSONL 每行只有 `type`、`uuid`、`parentUuid`、`isSidechain`、`sessionId`、`cwd`、`timestamp`、`message`，另加一行 `custom-title`；不写 `entrypoint`、`version`、`model`、`usage`、`permissionMode`。记录只有 `sessionId`、`cliSessionId`、`cwd`、`originCwd`、`title`、`createdAt`、`lastActivityAt`、`isArchived`，其余由官方客户端补全。
- 目标账号打开后，侧栏显示“标题（清理副本）”。目录未受信任时由官方在发送时弹确认，启动器不写信任配置。第一条消息由用户手动发送，计入目标账号额度。
- 日志只记账号编号和消息数量，不记标题、路径或正文。
- 全过程不启动 CLI、不发请求、不操作官方界面。官方客户端打开后的正常联网不受启动器控制。[Windows 待同步] 尚未实现。

### 登记到 Claude 侧栏（macOS）

- 保留手动添加与只读识别导入。按钮“同步到账号”（原“登记到账号”，2026-10-30 改名），从公共清单勾选项目并勾选一个或多个已创建的目标账号（运行中账号不可勾选）；逐个账号写入，已有同目录记录保持不变，不复制真实会话文件。完成后按账号报告新增／已有数量，并提示重新启动这些账号生效。目标须正常退出且不处于启动、检查或登录保护状态。源账号是否运行不影响目录前缀识别。
- 仅允许已验证的官方 Claude 版本：4.29.0（2026-10-28 实写并重启验收）、4.4212.0（2026-10-30 用户确认 02 侧栏仍显示 10-28 写入的空归档分组）。其他版本拒绝写入。目标 `claude-code-sessions` 下必须只有一个可安全访问的账号 UUID／组织 UUID 位置；缺失、多位置、链接、权限或格式异常时拒绝写入，不创建、猜测或复制身份目录。
- 仅生成七字段：全新 `sessionId=local_<UUID>`、真实 `cwd`／`originCwd`、固定标题“项目目录入口（无对话）”、新建时间、最近活动时间、`isArchived=true`。不复制来源名称、会话 ID、消息、权限、环境、MCP、Cookie 或凭据。每个目标生成独立 ID。
- 复用项目路径准入规则，批量拒绝主目录、根目录及系统临时目录。目标已有同目录记录时跳过；只读记录前缀，不解析后续内容。目标扫描上限为 5000 条记录／20000 个目录项，遇到不完整读取或未知记录前缀时拒绝登记，避免误判重复。
- 新记录 0600；同目录独占临时文件写完并 fsync 后，以不覆盖模式原子发布。每次发布前重新核对目标路径身份、目录状态及进程。成功部分不回滚删除，后续失败明确报告已添加和跳过数量，重试去重。启动器不能拦截从外部入口启动 Claude，因此操作期间不要从 Dock 或终端打开目标账号。
- 完成后由用户启动目标账号，在 Claude 的“分组和排序 → 显示 → 空分组”开启显示。启动器不编辑客户端浏览器数据库，不自动授予目录信任。目录会在侧栏显示“无活跃会话”，新会话仍走官方目录信任与账号自身设置。
- 空归档记录需保留，可能在归档列表中可见；移除启动器清单记录不删除客户端记录。第一版不提供批量撤销，不删除或覆盖任何已有会话。未来 Claude 更新、自动清理和长期保留仍需重新验证。
- 开发诊断 `--register-projects-from <源编号> <目标编号>` 仅预览计数；显式追加 `--apply` 才写入，复用相同版本、保护、进程、路径、存储及去重检查。此入口只从源账号记录前缀取得目录，绝不输出原始记录内容。

2026-10-28 实测：01 的三个真实目录以全新空归档登记到 02，侧栏出现对应分组且正常重启后保留；一个已信任目录的新草稿路径正确，另外两个进入对应目录的信任提示后取消。没有发送消息。原有目标记录元数据在登记前后保持不变，命令行和 GUI 重复登记均跳过三个已有目录。完整验收与限制见 STATUS。

### 公共清单存储与路径安全

- 保存位置：`~/Library/Application Support/Claude Launcher/projects.json`。格式为 `{"version":1,"projects":[{"id":"UUID","name":"名称","group":"分组","path":"绝对真实路径","lastAccount":0}]}`；数组顺序即显示顺序，`lastAccount` 为 0（未使用）或 1～10。
- 新文件权限为 0600，同目录临时文件写完后原子替换。清单只保存上述元数据，不包含登录信息或项目文件内容。写入失败保留之前的清单和界面数据。
- JSON 损坏或结构非法时提示用户，把原文件改名为同目录的 `projects.json.corrupt-<UUID>` 保留，不覆盖原始内容；保留失败或遇到不安全的存储路径时停止写入并提示。未知版本保留原文件并停止写入，避免覆盖未来版本的数据。
- 项目路径必须为绝对路径，添加时标准化并解析为真实目录。拒绝账号数据目录（`Claude`、`Claude-Second`、`Claude-Profile-NN`）及其子目录、路径中包含 `ClaudeCodeConfig` 的目录、启动器自己的数据目录及应用包。别名指向这些位置同样拒绝；重复真实路径不重复添加。
- 添加用户主目录或根目录需要额外确认。只检查目录元数据和可访问性，不读取项目文件内容；不要求目录可写，允许只读项目。
- 已记录路径不存在、不是目录或已指向其他位置时标记“不存在”；无读取／遍历权限时标记“无权限”。不自动新建、不迁移、不替换路径；打开前重新校验，失效或变为受保护路径时拒绝交接。父目录授权可能涉及系统隐私提示，由用户自行决定，启动器不修改系统权限。

### 验证

## 本地界面用量（macOS）

- macOS 1.7.9 起，只读官方 Claude Code 已显示的用量控件。Windows 见本节末尾 [Windows]。`UsageHistory.m` 留作历史实现，不再编译或调用；不再读取 `plan-usage-history.json` 或访问 Claude Safe Storage，也不回退到旧历史。仅为缓存归属定向读取已获授权的非登录 `lastActiveOrg` 字段并生成 SHA-256 指纹，不读取登录字段、不解密。
- 先用官方主进程可执行路径、内核启动参数及固定账号目录定位 PID，排除 Helper、GPU、renderer、CLI 和未管理进程。同账号多个主进程、路径异常或进程扫描失败时不显示数值。读取前后重核 PID、进程启动时间、目录身份和组织选择指纹；读取后再扫描进程，异步返回时复核。Cookies／journal／wal／shm 元数据变化仅触发组织字段重新核对，普通 Cookie 写入不会清空观察记录。固定查询只选官方域名、根路径、未过期的 lastActiveOrg；schema 24 / v10、只读 immutable、不复制、不建锁或日志，拒绝 WAL、活动日志、歧义及读取期间的变化。只保留指纹，既不保存原值也不访问钥匙串。元数据未变时复用指纹最多 60 秒；它不证明服务器身份或尚未落盘的组织切换。
- 只通过系统辅助功能复制现有 AX 属性，不执行动作、不激活 Claude、不启用调试。当已验证官方主进程的 `AXManualAccessibility` 明确为 false 时，可按 Electron 官方文档将它设为 true，仅启用该进程的本机网页辅助功能树；这是唯一允许设置的用量相关 AX 属性，不是系统权限授权，也不导航或刷新页面。不能将此初始化步骤描述为“只复制属性”。需要用户已经授予启动器的辅助功能权限；没有权限就显示“需辅助功能权限”，不自动弹出授权或改 TCC。固定签名身份不变。
- 限定官方 `https://claude.ai/epitaxy` Code 首页及 `https://claude.ai/epitaxy/…` 对话页面，拒绝嵌套浏览器页面。仅解析用量弹出按钮和相邻、带官方用量设置链接的面板；读取五小时及“每周 · 所有模型”，不将上下文 token 百分比或模型专属周限额混入。文本正文、输入框内容不读取。多个用量页面、重复或矛盾指标、遍历预算耗尽、未知格式均不采用新的不确定结果。
- macOS 1.7.10 起，打开／恢复启动器并进入实例页、实例页重新获得焦点、返回实例页、或在该页点击才读取一次；1 秒内重复焦点／点击合并。窗口内鼠标抬起通过本应用的本地事件监视器观察，不监听其他应用输入，不消费或合成事件。持续停留、普通界面变化及原进程刷新定时器不得触发用量控件读取或组织指纹核对。1.7.11 增加用户确认的例外：按 PID 监听 Chromium 的 AXExpandedChanged，只有正确官方 Code 页的用量按钮变为展开且该 Claude 进程在前台时，为该账号读取一次。关闭、非用量按钮及同一次展开的重复通知不采集；200 ms 后单次读取，忙碌时按 PID 合并排队；不是后台定时器。已开始的一次读取可完成；进程状态定时器继续只做原有状态管理和缓存显示，进程退出／变化时隐藏旧值。
- 新五小时窗口尚未开始（官方提示发送第一条消息后开始计时）时，官方按钮改为显示“每周 · 所有模型”（实测 `用量：每周 · 所有模型：11%周三19:00 重置`）。此时按钮只提供周值，五小时保留上次观察值和原时间，不推算为 0%；用户手动展开该按钮的弹窗同样触发一次读取，面板中五小时指标按官方显示更新，面板必须与按钮周值一致。英文周按钮格式未实测，暂不识别。
- 五小时按钮在弹窗关闭时可提供数值；周限额只在用户主动查看启动器或手动展开官方弹窗触发读取时，官方节点已经可读才取得。启动器不会代为展开，也不承诺捕获每次短暂出现的弹窗。首次未观察到周限额显示“—／尚未观察到”。此限制不能用历史、推算或额外查询补齐。
- 两项各有独立观察时间。卡片只显示观察时间 HH:mm:ss（跨日为 MM-dd HH:mm），不加“读取于／上次显示”前缀，读取成功时也不显示来源说明行；周控件关闭后，只有账号、进程及组织指纹一致才可保留最近观察值和原时间。五小时的新读取不会刷新周限额时间。悬停可看完整日期及官方原始重置说明；不推算重置、不将观察时间当作服务器采样时间。
- 用户要求记录最近查看结果：仅把两项百分比、重置说明、各自观察时间和用于匹配的进程／目录元数据及组织指纹保存到启动器自己的 `usageInterfaceObservations` 偏好，不存页面／会话标识、正文或凭据，不写官方目录。重启启动器先校验记录格式和时间，再匹配当前主进程、目录和组织指纹后恢复，均标“上次显示”。同账号切换 Code 对话或关闭弹窗不会丢失已观察值；界面暂时不可读可继续显示已验证归属的最近观察值。账号／PID／进程启动时间／目录／组织指纹确认改变时清除；登录保护、进程歧义、权限丢失或身份文件写入中则隐藏，后续身份一致时恢复。关闭显示设置清空缓存。Claude 退出后（账号无主进程）卡片继续显示该账号最后保存的观察值和原观察时间，标“Claude 未运行 · 上次记录”，不再清成“尚未观察到”（2026-10-29 用户要求）；重新启动后仍须核对新进程归属再读取，新进程不继承旧值参与合并。设置沿用旧 `showUsageHistory` 键以保持开关选择，名称改为“显示本地界面用量”。
- 每次读取最多 16000 次属性访问、1.5 秒预算；只处理 40 层内的用量布局，更深分支跳过（不是用量候选），重复结构节点去重；普通节点只批量读取角色与子节点，单次系统 IPC 超时 0.1 秒；首次启用网页辅助功能树后，可在本次主动查看的总计 2.5 秒预算内等待并重读准备好的结构，不设置后台定时器；超时／读取中页面变化不采用新结果。只注册用量展开通知，不注册布局／值变化等广泛通知；不调用任何官方查询 IPC 或认证提供器。
- 2026-10-30（Claude 4.4212.0）：长对话会让遍历先耗尽预算，账号 01 曾显示“界面读取未完成”。保留子节点倒序遍历（输入框与用量按钮位于对话之后）。预算耗尽时，仅在传入窗口数为 1、已识别 Code 页面数为 1、页面 URL 未变化、恰好一个“界面已读取”结果，且除已识别的超大末尾分支外没有未遍历的兄弟分支时保留结果；否则返回“界面读取未完成”，不采用数值。页面在读取期间变化、无匹配或多个匹配仍按未完成／待核对处理。结束时的 URL 复核不受预算限制，只多读一次。
- `--usage-interface-check` 只输出账号编号、读取状态、两项是否观察到及耗时；不输出百分比、页面会话标识或正文。从终端执行时权限归属可能与 GUI 启动不同，不据此自动修改授权。GUI、合成自检和离屏渲染分开报告。旧 `--usage-history-check` 已移除。限制与研究证据见 [用量调查](USAGE-RESEARCH.md)。

- 读取方式：Windows UI 自动化（UIA）只读。从 `Core.Scan` 核实的官方主进程（每账号恰好一个）的最大可见顶层窗口进入，只批量读取控件类型与“是否支持展开”；只对 Document 读取地址、对支持展开的 Button 读取名称；只有经过官方用量设置链接核实的弹窗面板内才读取文字、链接与进度值。不调用 Invoke／Expand／SetFocus 等任何模式方法，不设置属性，不激活窗口，不读取面板以外的文本、编辑框、列表或链接内容（这些分支不进入）。首次连接会使 Chromium 为该进程启用网页辅助功能树并保持到进程退出（实测首轮只有原生外壳，约 2.5 秒后可读）；这是 UIA 客户端连接的固有效果，与 macOS 的 `AXManualAccessibility` 性质相同，不改系统设置、不加启动参数。

- 面板（D3，2026-10-29 实测）：展开后 Code 页内出现 Window「用量」，含链接 `https://claude.ai/settings/usage` 与「使用限额」分组：Text「5 小时限额」、Text「HH:MM 重置」、ProgressBar「5 小时限额」（RangeValue 0～100），每周同理（「每周 · 所有模型」）。规则同 macOS：只解析含该链接（12 层内）的 Window；指标名只认「5 小时限额」「5-hour limit」「每周 · 所有模型」「Weekly · all models」，模型专属周限额与上下文不采用；进度值 0～100；同一指标重复、面板多于一个、面板缺少与按钮同项的指标或数值与按钮不一致时整次不采用（“界面数据待核对”）。没有用量按钮时不采用面板。
- 归属（无组织指纹）：身份 = 账号编号 + PID + 进程启动时间（UTC ticks）+ 账号目录（01 为默认）。读取前后各扫描一次进程，身份不一致则丢弃本次结果；任一项变化即清除缓存与保存记录。限制：同一账号目录内切换组织后，进程重启前旧值可能被当作新组织的值；卡片悬停说明此限制。
- 触发：同 macOS 1.7.10——启动器显示／激活且停在实例页、切换到实例页、在实例页点击时读取一次；1 秒内合并。没有定时器，进程刷新定时器不触发读取。同 macOS 1.7.11（D3）：对每个只有一个主进程且有可见窗口的账号，在该进程窗口上注册 UIA 的 ExpandCollapseState 属性变化通知（只此一种）；只有官方 Code 页中名称可解析的用量按钮变为展开、且该 Claude 窗口在前台时，200 ms 后为该账号读取一次（不要求启动器窗口可见）；关闭、其他按钮及同一次展开的重复通知不采集，读取忙碌时按 PID 排队合并。注册失败不重试；进程退出／变化、登录保护、扫描失败或关闭显示时注销。登录保护中、扫描失败、窗口隐藏或最小化时不读取。托盘中无可见窗口的实例显示“未观察到窗口”，不为读取而唤出。
- 预算：后台线程执行，每账号首轮 1.5 秒；首轮未见 Code 页面时同一次查看内最多等到 2.5 秒重读；遍历 40 层、16000 个节点上限；超时的线程结果丢弃，前一次读取未结束时不开始新读取。
- 显示与保存：卡片右侧两行「5小时限额」「周限额」，百分比与观察时间（HH:mm:ss，跨日 MM-dd HH:mm），悬停显示完整时间与官方重置说明；未读到显示“—／尚未观察到”和状态说明。读取中保留旧值。观察记录（两项百分比、重置说明、观察时间和身份）写入 `%LOCALAPPDATA%\Claude-MultiLauncher\usage-observations.json`（原子写入，version 1），不存页面、会话、正文或凭据；重启后逐项校验，身份与当前进程一致才恢复。关闭「显示本地界面用量」立即停止读取、清空缓存并删除该文件。

## 用量趋势与轮换建议（macOS，2026-10-30）

- 只记录启动器本来就观察到的数值：每次界面读取成功，把本次真正读到的 5 小时／周百分比（沿用旧观察时间的值不记）追加到启动器自己的 `usageTrend` 偏好。每点仅含账号编号、时间、两项百分比；不含重置文本、页面、会话、组织或凭据。
- 保留 8 天、最多 4000 点；同账号数值未变且距上次不足 15 分钟不重复记录。关闭“显示本地界面用量”时与最近观察值一起清除。读取时逐项校验（编号 1～10、时间有限且在保留期内、百分比 0～100），无效项丢弃。
- 账号页下方“用量趋势”区（2026-10-30 起取代实例页弹窗；账号页整体纵向滚动）：顶部建议条显示建议账号并可直接启动／打开（复用正常流程）；每个已有账号一张卡片，含最新 5 小时／周数值、更新时间、用完估算与近 7 天图（深色粗线加面积为周限额，浅色细线为 5 小时限额，按日期刻度；数值回落视为重置，不跨重置连线）；无记录账号显示空状态；关闭“显示本地界面用量”时只显示开启提示。有数据时给出“按当前速度约多久用完”（同一重置周期内、跨度至少 20 分钟且上升，最新点不超过 6 小时），并建议下一个使用最近观察到周用量最低的账号（相同时比 5 小时）。不额外读取或查询任何东西。

## 账号配置同步（macOS，2026-10-30）

- 账号页“同步配置…”：选择来源账号与一个或多个目标账号，在 Claude Code 配置目录之间本地复制（01 为 `~/.claude`，02～10 为账号目录下 `ClaudeCodeConfig`）。目标须已有该目录。
- 白名单：顶层 `settings.json`、顶层 `*.md`（如 CLAUDE.md 及其引用文件），以及 `skills`、`agents`、`commands`、`output-styles` 下的条目。绝不读取或复制 `.claude.json`、凭据、会话、历史、projects、plugins、缓存等其他内容。
- `settings.json` 若含 `apiKeyHelper`／`awsAuthRefresh`／`awsCredentialExport`／`otelHeadersHelper`，或 `env` 中键名含 TOKEN、KEY、SECRET、PASSWORD、PASSWD、CREDENTIAL、AUTH、COOKIE，标为“含凭据”并拒绝同步。
- 第二步预览每个条目在各目标中的状态（缺少／相同／不同／含凭据／不安全），默认只勾选缺少项；“不同”只有勾选“覆盖目标中内容不同的条目”才替换，旧内容移到废纸篓。符号链接按链接复制，不跟随；来源硬链接文件、超过 50MB／5000 个文件的目录，以及目标中是链接或非目录的分类目录都视为不安全。
- 链接模式（2026-10-30 用户要求“后续也能同步”，默认开启）：目标放置指向来源条目绝对路径的符号链接，之后在任一账号修改都直接生效，无需后台任务或再次同步。来源条目本身是链接时（如 skills）仍按原目标复制链接。目标已是指向来源的链接显示“已链接”，不再处理；勾选覆盖时“相同”的拷贝也改成链接（旧拷贝进废纸篓）。共享意味着目标账号写入该文件也会改到来源；若客户端以“写临时文件再替换”的方式保存，链接会变回普通文件，预览中显示为“相同”或“不同”，可重新同步。关闭链接模式时按拷贝处理。
- 写入先在同目录生成临时副本（或临时链接），再以不覆盖方式移动到位；中途失败即停止并报告已完成数量。完成后提示“Claude Code 新会话生效；正在运行的账号建议重启”，并记录日志（只含账号编号与计数）。目标运行中也允许同步，不读写 Claude 桌面端数据。

> - **[Windows 差异]** 回滚：Setup 先卸载旧版再安装，新版安装失败时旧版已卸载，无法自动回滚到旧版（账号数据不受影响，可重新运行 Setup 或从 GitHub 下载）。旧版卸载失败、启动器无法正常关闭时则中止并保留旧版。
> - **[Windows 差异]** `minimumOS` 每段允许 1～5 位数字（Windows 版本号第三段为构建号，如 `19041`）。macOS 端解析 `latest-macos.json` 时可保持 1～3 位。
> - 兼容 1.2.0：发布脚本额外签发旧格式 `latest.json`（签名原文 version、file、size、sha256），指向同版本的单个 `ClaudeLauncher-x.x.x.0.exe`，1.2.0 客户端用 `--apply-update` 原地替换；新程序保留该入口。旧清单只放自建服务。
> - 发布流程与上文的差别：macOS DMG 由 macOS 端先上传到草稿 Release，发布脚本下载并核对 macOS 给出的 size/sha256，再上传 Setup 与两份清单，切换自建服务清单后把草稿转为正式；上传后先经 GitHub API 下载草稿附件逐字节核对（不符则停在草稿、原 Latest 与自建服务不变），转正式前记下上一版 Latest；只有内容确认不符才回滚（恢复自建清单、改回草稿并显式恢复上一版 Latest），latest/download 最多等 10 分钟，仅缓存未更新或自建服务暂时不可达时保留发布并以状态 2 退出。

两端共用一套发布与校验流程。来源有两个，内容相同、校验相同：放在哪里不影响安全，安全只靠签名。

### 版本

- 版本号格式 `主.次.修订`（如 `1.7.0`）。Windows 程序集版本写成 `1.7.0.0`，清单里仍写 `1.7.0`。
- 两端版本号各自递增，不要求一致（2026-10-28 用户决定）。客户端只读本平台清单，版本不同不影响更新。
- 只接受比当前更高的版本，不降级。

### 清单

每个平台一个清单：`latest-macos.json`、`latest-windows.json`。字段：

| 字段 | 说明 |
|------|------|
| `platform` | `macos` 或 `windows` |
| `version` | `1.7.0` |
| `file` | macOS：`ClaudeLauncher-1.7.0.dmg`；Windows：`ClaudeLauncherSetup-1.7.0.exe`。只用 ASCII：GitHub 会改写附件名中的非 ASCII 字符（实测 `Claude多开启动器-1.7.0.dmg` 变成 `Claude.-1.7.0.dmg`），回退下载会 404。 |
| `size` | 字节数，上限 50 MB |
| `sha256` | 小写十六进制 |
| `minimumOS` | macOS `12.0`；Windows `10.0.19041` |
| `signature` | Base64，RSA-3072 + SHA-256，对下面的签名原文签名 |

签名原文（UTF-8，每行以 `\n` 结尾，顺序固定）：`platform`、`version`、`file`、`size`（十进制）、`sha256`。

- 共用密钥：两端内置同一把公钥 `windows/assets/update-public-key.xml`；私钥只在 Windows 发布机（DPAPI 保护），不进仓库、不出现在日志。
- macOS 独立密钥（2026-10-28 用户同意，1.7.4 起内置）：Mac 发布机生成自己的 RSA-3072 私钥，只存在该 Mac 的钥匙串，公钥以同样的 RSAKeyValue XML 提交为 `resources/update-public-key-macos.xml`。Mac 客户端对 `latest-macos.json` 接受共用公钥或 Mac 公钥任一验签通过。过渡版（第一个内置 Mac 公钥的版本）仍由 Windows 发布机用共用密钥签名；之后 Mac 版本由 Mac 发布机自行签名发布。Windows 清单只认共用密钥。
  - 【macOS 差异】包内文件名为 `macos-publisher-key.xml`：NSBundle 把以 `-macos` 结尾的资源当作平台变体，会在查找 `update-public-key.xml` 时返回 `update-public-key-macos.xml`（实测），导致共用公钥加载不到。仓库路径仍为 `resources/update-public-key-macos.xml`。
  - Mac 私钥创建为不可导出（用户选择不备份），只能在生成它的这台 Mac 上签名。这台 Mac 丢失或重装时：由 Windows 发布机用共用密钥继续为 Mac 签名（1.7.4 起的客户端两把都认），或生成新的 Mac 密钥并随一个共用密钥签名的版本发布新公钥。
- 清单大于 16 KB、字段格式不符、文件名与版本不对应、签名无效，一律拒绝。下载后大小或 SHA-256 不符同样拒绝并删除临时文件。
- 兼容：在所有 1.2.0 客户端更新到新协议前，服务器继续提供旧的 `latest.json` 与 `ClaudeLauncher-x.x.x.x.exe`。

### 来源与回退

1. **GitHub Releases（唯一来源，2026-10-28 用户决定）**：`https://github.com/wyl20020808/ClaudeLauncher/releases/latest/download/latest-<平台>.json` 与同一 Release 中的安装包。自建更新服务不再作为客户端来源：macOS 自 1.7.8 起移除；Windows 于 feature/windows-update-boundary 移除（随下一个 Windows 版本发布）。此前的“自建优先、回退 GitHub”与 1.7.6 的“取较高版本”随之停用。
2. 取不到有效清单、验签失败或下载失败：提示原因，并提供“前往 GitHub 下载”按钮打开 Releases 页面，由用户手动下载安装。

检查时机：启动器每次打开时检查一次，以及用户手动点“检查更新”；不定时、不在后台重复。两者都只在设置中开启了更新时进行（默认关闭）。启动时的检查只在发现新版本时提示，失败只记日志。

只用 HTTPS，不跟随跳转到其他域名（GitHub 下载跳转到 `objects.githubusercontent.com`、`release-assets.githubusercontent.com` 除外），请求有超时与大小上限。

更新过程界面（两端）：确认“立即更新”后显示进度窗口，依次为“下载 → 校验 → 安装”。下载显示真实进度（已下载／总大小、百分比、来源），可取消，取消即删除临时文件、不做任何改动，关闭窗口视为取消；校验为不定进度，也可取消；校验通过后提示“启动器即将关闭，完成后会自动重新打开”，约 2 秒后退出并由替换步骤完成安装。不退出、不结束任何 Claude。

macOS 每次开始或取消更新都递增任务编号；进度、下载结果、校验结果和延迟安装均核对编号。旧任务只清理自身临时文件，不改变新任务状态或窗口，不启动安装。

### 发布流程（发布机）

一个脚本完成：构建两端安装包 → 计算 SHA-256 → 用私钥签名两份清单 → 上传自建服务 → `gh release create v<版本>` 上传两份清单与两个安装包 → 两个来源各下载一次并验签核对。任何一步失败都不发布半成品。

复核加固（macOS `publish-macos.sh` 与 Windows `publish-release.ps1` 一致，Windows 于 feature/windows-publish-hardening 对齐）：
- 上传后先经 GitHub API 下载草稿附件，核对附件清单与逐字节内容（不经 latest/download 缓存）；不符则停在草稿，原 Latest 不变（Windows 另保证此时尚未切换自建服务清单）。
- 转正式前记下上一版 Latest。只有内容确认不符才回滚：改回草稿，并显式把上一版设回 Latest（Windows 同时恢复自建清单），避免 GitHub 自动选中更早版本导致 latest/download 失效。
- latest/download 最多等 10 分钟；仅缓存未更新（Windows 另含自建服务暂时不可达）时保留发布、提示稍后复核并以状态 2 退出。
- macOS 正式发布后的 Windows 清单、DMG、Setup 复核若下载失败，同样保留发布并以状态 2 提示“待复核”；只有成功下载后确认内容或哈希不符才回滚。
- `--dry-run`／`-DryRun` 只构建、签名、本地校验与带入核对，不创建 Release；Windows 允许测试密钥，同名 Release 已存在时只警告。

**每个正式 Release 都必须同时包含两端当前的清单与安装包。** GitHub 回退地址 `releases/latest/download/` 只指向最新的一个 Release；若只放一个平台的文件，另一平台回退时会 404。

- 两端同时发布：标签 `v<版本>`。
- 只发布一个平台：标签 `windows-v<版本>` 或 `macos-v<版本>`，另一平台的清单与安装包从上一个最新 Release 原样带入（验签并核对哈希后再上传，不重新签名），自建服务中另一平台的清单不改。Windows 发布脚本已支持只发布 Windows；Mac 发布脚本同样从上一个最新 Release 带入 Windows 文件（已签名，无需私钥）。两端版本不要求一致，哪端有新功能哪端就发，另一端之后再跟上。只发布 macOS 时，自建服务由同步自动更新，不需要 Windows 发布机操作（Mac 独立密钥生效之后）。

### 安装：先卸载旧版，再装新版

通用规则：

- 只卸载**启动器程序本身**。**任何情况下都不删除账号数据目录**（macOS `~/Library/Application Support/Claude*`，Windows `%APPDATA%\Claude-*`、`Claude-Data` 等）、Code 配置或启动器偏好。
- 只正常退出**启动器**，不退出、不结束任何 Claude 实例。
- 先校验新包，校验通过才动旧版；新版装好并校验通过后才清理旧版，失败自动回滚到旧版。
- 新旧版本必须由同一证书签名，否则拒绝更新（避免授权失效和被替换成伪造程序）。

**Windows（Setup 安装程序）**

- 用固定 AppId 检测已安装版本（注册表卸载项）。已安装时：提示“检测到已安装 x.y.z，将先卸载再安装新版”，正常关闭运行中的启动器，静默运行旧版卸载程序，确认卸载完成后再安装新版。
- 旧版卸载失败则中止安装，保持旧版可用，并提示原因。
- 自动更新下载的就是这个 Setup，以静默参数运行，完成后重新启动启动器。

**macOS（应用内更新与 DMG）**

- 自动更新：下载 DMG → 校验 → 挂载 → 校验其中应用的签名要求与当前应用一致 → 正常退出启动器 → 把旧版改名为备份 → 复制新版到原位置 → 校验新版签名 → 成功后把备份移到废纸篓（即“卸载旧版”）并启动新版；任一步失败则删掉不完整的新版、恢复备份并启动旧版。
- 手动 DMG 安装：拖到“应用程序”时由系统提示“替换”，等同于先移除旧版再安装。DMG 内附一份简短说明。
