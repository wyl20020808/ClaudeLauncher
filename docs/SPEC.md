# 跨平台行为规格

macOS（`src/main.m`）和 Windows（`windows/`）各自原生实现，共同遵守本规格。macOS 1.6 是参考实现；规格变化时两端同步修改并在 STATUS 记录。

2026-10-28 隔离加固按用户要求仅修改 macOS；下文标注的加固行为在 Windows 尚未同步，不代表 Windows 已通过对应验收。

## 账号与目录

| 编号 | 数据目录 | Claude Code 配置 |
|------|----------|------------------|
| 01 | 官方默认 userData（位置由平台和安装方式决定），不传覆盖参数 | 官方默认（`~/.claude`） |
| 02 | `<基础目录>/Claude-Second` | `<数据目录>/ClaudeCodeConfig` |
| 03～10 | `<基础目录>/Claude-Profile-NN` | `<数据目录>/ClaudeCodeConfig` |

- 基础目录：macOS 为 `~/Library/Application Support`；Windows 为 `%APPDATA%`（沿用已有 02/03 数据）。
  - **[Windows 差异，已确认]** MSIX 版 01 的默认 userData 实测为 `%LOCALAPPDATA%\Claude-Data\claude_pzs8sxrjxfjjc`，不在基础目录下；商店版还可能把目录虚拟化到 `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\<名称>`，Windows 端按同一账号识别和校验。见 `windows/README.md`。
- 02～10 启动参数 `--user-data-dir=<数据目录>`，环境变量 `CLAUDE_CONFIG_DIR=<数据目录>/ClaudeCodeConfig`。
- 界面只显示本机已有的账号（数据目录存在、正在运行或正在启动），按编号紧凑排列；没有任何账号时显示空状态提示。“新建实例”创建 01～10 中编号最小的未使用账号。编号与目录映射不变。
- 已有目录直接复用，不迁移、删除、覆盖、修改权限。新目录仅本人可访问。
  - **[Windows 差异，已确认]** 不设置 ACL，新目录继承 `%APPDATA%` 默认权限（本人、SYSTEM、Administrators），与“仅本人可访问”意图一致。
- 01 的子进程环境不得带 `CLAUDE_CONFIG_DIR`。Windows 用 `UseShellExecute=false` 会继承启动器环境，因此须显式移除；macOS 经 LaunchServices 启动，不继承启动器环境，只附加显式设置的变量，无需处理。

### macOS：Code 配置状态（Windows 待同步）

- 01 显示“Code 默认”，仍与普通终端 Claude Code CLI 共用默认用户配置。
- 02～10 未运行显示“Code 待启动”；已运行但启动来源未确认显示“Code 未确认”。已有目录、正在运行和旧版启动记录均不能证明独立配置已生效。
- 仅本次启动器通过 LaunchServices 指定 `CLAUDE_CONFIG_DIR`，返回一个启动时间不早于请求时间、且主程序路径和账号参数匹配的新进程时，记录该进程对象。后续扫描仍为同一存活进程才显示“Code 已指定”。这仅表示启动参数已指定，不能宣称 Code 实际存储已验证。
- 不读取进程环境变量；记录仅在内存中保留。启动器重启、目标退出、PID 改变或重复主进程时，不能继续沿用已指定状态。旧实例由用户保存工作并正常退出后重新启动，不自动重启，不迁移旧配置或历史记录。

### macOS：登录保护（Windows 待同步）

- “···”菜单提供“登录 / 重新登录保护…”。首次创建账号空间时弹出提醒，用户选择“直接创建”或“进入登录保护”，不强制保护。
- 进入前与确认后重新扫描：其他管理/未管理的官方主进程、目标重复主进程、其他账号正在检查或启动、任何扫描错误都阻止进入。不会退出、登出或强杀任何实例。
- 保护账号编号保存在启动器自身偏好中，重开启动器仍保留。保护期间不允许通过启动器打开其他账号、新建实例或删除受保护账号；目标检查和启动仍可正常完成。
- 用户自行完成登录或取消浏览器登录流程，再确认“结束保护”。存在检查或启动操作时暂不允许结束，避免后台操作跨越保护状态。
- 保护不截获回调、不读取身份，不能约束 Dock、终端等外部启动。发现外部实例时持续提示停止登录；不能保证回调一定属于目标账号。

## 进程识别

- 只认官方主程序路径；排除 Helper、GPU、renderer（参数含 `--type`）以及 Claude Code CLI。
- 从系统读取命令行参数解析 `--user-data-dir`（支持 `=` 与空格两种形式）：无参数为 01；重复参数、相对路径或缺值视为无法识别并暂停操作；不在 01～10 内的目录记为未管理实例。
- 不读取进程环境变量（可能含凭据）。
- 任何官方实例无法核对参数时，暂停启动，不重复启动、不结束进程。

## 启动与激活

- 运行中：按 PID 激活。激活前再次核对该 PID 的路径和账号；不以按程序名打开代替。
  - **[Windows 例外，已确认]** 主进程在托盘中、按 PID 找不到可见窗口时，允许用同一 `--user-data-dir` 再启动一次，由 Claude 单实例锁（4.29 含 `requestSingleInstanceLock`，按 userData 区分）转交已有进程显示窗口。必须同时满足：该账号恰好一个已核实主进程且无可见窗口；使用该 PID 的可执行文件；之后重新扫描，若同账号出现第二个主进程则报错，不结束任何进程。macOS 保持纯 PID 激活，最小化窗口经辅助功能恢复。
- 同一账号多个主进程：报错，不激活、不结束任何实例。
- 未运行：校验存储后以新实例启动；启动中禁用按钮防重入，35 秒未出现主进程报失败。
- 启动器单实例；再次打开时唤起已有窗口。关闭启动器不退出 Claude。
- **[macOS 加固，Windows 待同步]** 递归存储检查放到后台，不占用界面主线程；同账号检查期间禁止重复打开/删除。不同账号可独立检查，失败只记录在该账号。完成后重新扫描进程、检查保护状态及根目录元数据。原本要激活的 PID 若退出或被替换，不自动重启，也不静默切换到另一个 PID。删除同样在后台检查完成后再扫描和校验路径。
- **[macOS 加固，Windows 待同步]** LaunchServices 请求超过 35 秒仍未回调时报告超时，但继续保留该账号的启动中状态，禁止重试及其他账号进入登录保护，直到系统返回。不会强制结束启动请求或 Claude。
- 无法识别的官方进程仍触发全局暂停；这是防止重复启动的保护，不因降低耦合而取消。

## 存储校验

只检查元数据，从不读取内容。目录及各级上级不得为链接或非目录；以下存储项不得为链接、非本人所有、普通文件硬链接：
`Cookies`、`Cookies-journal`、`Network`、`Local Storage`、`Session Storage`、`IndexedDB`、`Partitions`、`Local State`、`Preferences`、`config.json`、`Cache`、`Code Cache`、`Service Worker`、`ClaudeCodeConfig`。

Windows 对应：重解析点（符号链接、junction）等同链接；硬链接数通过文件信息查询。所有者按 ACL 所有者 SID 判断，以管理员身份创建的文件属于 Administrators 组，会被拒绝。

## 更新与安装

两端共用一套发布与校验流程。来源有两个，内容相同、校验相同：放在哪里不影响安全，安全只靠签名。

### 版本

- 统一版本号 `主.次.修订`（如 `1.7.0`）。Windows 程序集版本写成 `1.7.0.0`，清单里仍写 `1.7.0`。
- 只接受比当前更高的版本，不降级。

### 清单

每个平台一个清单：`latest-macos.json`、`latest-windows.json`。字段：

| 字段 | 说明 |
|------|------|
| `platform` | `macos` 或 `windows` |
| `version` | `1.7.0` |
| `file` | macOS：`Claude多开启动器-1.7.0.dmg`；Windows：`ClaudeLauncherSetup-1.7.0.exe` |
| `size` | 字节数，上限 50 MB |
| `sha256` | 小写十六进制 |
| `minimumOS` | macOS `12.0`；Windows `10.0.19041` |
| `signature` | Base64，RSA-3072 + SHA-256，对下面的签名原文签名 |

签名原文（UTF-8，每行以 `\n` 结尾，顺序固定）：`platform`、`version`、`file`、`size`（十进制）、`sha256`。

- 两端内置同一把公钥；私钥只在发布机（Windows，DPAPI 保护），不进仓库、不出现在日志。
- 清单大于 16 KB、字段格式不符、文件名与版本不对应、签名无效，一律拒绝。下载后大小或 SHA-256 不符同样拒绝并删除临时文件。
- 兼容：在所有 1.2.0 客户端更新到新协议前，服务器继续提供旧的 `latest.json` 与 `ClaudeLauncher-x.x.x.x.exe`。

### 来源与回退

1. **自建服务**：`<自建地址>/latest-<平台>.json` 与同目录安装包。macOS 在构建时通过 `UPDATE_BASE_URL` 配置，未配置则直接使用 GitHub。
2. **GitHub Releases**（自建失败时自动回退）：`https://github.com/wyl20020808/ClaudeLauncher/releases/latest/download/latest-<平台>.json` 与同一 Release 中的安装包。
3. 两处都失败：提示原因，并提供“前往 GitHub 下载”按钮打开 Releases 页面，由用户手动下载安装。

只用 HTTPS，不跟随跳转到其他域名（GitHub 下载跳转到 `objects.githubusercontent.com` 除外），请求有超时与大小上限。检查更新由用户触发或启动后低频进行，失败不影响正常使用。

### 发布流程（发布机）

一个脚本完成：构建两端安装包 → 计算 SHA-256 → 用私钥签名两份清单 → 上传自建服务 → `gh release create v<版本>` 上传两份清单与两个安装包 → 两个来源各下载一次并验签核对。任何一步失败都不发布半成品。

### 安装：先卸载旧版，再装新版

通用规则：

- 只卸载**启动器程序本身**。**任何情况下都不删除账号数据目录**（macOS `~/Library/Application Support/Claude*`，Windows `%APPDATA%\Claude-*`、`Claude-Data` 等）、Code 配置或启动器偏好。
- 只正常退出**启动器**，不退出、不结束任何 Claude 实例。
- 先校验新包，校验通过才动旧版；新版装好并校验通过后才清理旧版，失败自动回滚到旧版。
- 新旧版本必须由同一证书签名，否则拒绝更新（避免授权失效和被替换成伪造程序）。

**Windows（Setup 安装程序）**

- 用固定 AppId 检测已安装版本（注册表卸载项）。已安装时：提示“检测到已安装 x.y.z，将先卸载再安装新版”，正常关闭运行中的启动器，静默运行旧版卸载程序，确认卸载完成后再安装新版。
- 旧版卸载失败则中止安装，保持旧版可用，并提示原因。
- 自动更新下载的就是这个 Setup，以静默参数运行，完成后重新启动启动器。

**macOS（应用内更新与 DMG）**

- 自动更新：下载 DMG → 校验 → 挂载 → 校验其中应用的签名要求与当前应用一致 → 正常退出启动器 → 把旧版改名为备份 → 复制新版到原位置 → 校验新版签名 → 成功后把备份移到废纸篓（即“卸载旧版”）并启动新版；任一步失败则删掉不完整的新版、恢复备份并启动旧版。
- 手动 DMG 安装：拖到“应用程序”时由系统提示“替换”，等同于先移除旧版再安装。DMG 内附一份简短说明。

## 禁止事项

- 不修改、复制、重签官方 Claude 程序（仅可复制图标）。
- 不读取、复制、打印凭据；登录由用户完成。
- 不强杀 Claude；不修改系统权限或安全设置。
- 不伪装设备指纹或网络出口。
- 删除账号（2026-10-28 用户要求恢复）：仅通过“···”菜单，二次确认后移到废纸篓（可恢复），不永久删除；01 默认目录不可删；运行中或启动中不可删；删除前重新扫描进程并校验路径。
  - **[Windows 待同步]** 规格已恢复删除：Windows 可重新开放回收站删除入口，按上条约束对齐（01 不可删、运行中不可删、二次确认）；“删除未完成”的重试保留。

## 自检

每端提供 `--self-test`：账号映射、Code 配置映射唯一性、参数解析（含 Helper/CLI 排除、异常参数）、路径校验（链接、硬链接拒绝），只用随机合成目录并清理。

macOS 加固自检还覆盖：登录保护准入、进行中操作和删除互斥、检查期间 PID 退出/替换及保护状态变化、保守 Code 状态、并发元数据检查与主线程回调、深层 Code 存储链接拒绝。自动检查不代替 GUI 或真实账号登录验收。

Windows 端的 `ClaudeLauncher.exe` 是 GUI 程序，需用 `ClaudeLauncher.exe --self-test | Write-Output` 运行，才会等待退出并显示结果。
