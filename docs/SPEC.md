# 跨平台行为规格

## 本地安全与可操作界面（2026-10-28，macOS feature/local-settings）

本节优先于下方旧版本更新描述。产品核心规则：管理器不向 Claude、Anthropic 或其 Cloud、API、遥测、登录服务发请求，不读取凭据，不通过 CLI、浏览器或官方界面刷新间接查询。设置不改变 Claude 的登录、会话、目录或运行状态。用户主动使用既有启动／激活功能时，官方客户端自身的正常联网不由管理器控制。规则写入根目录 AGENTS.md，后续两端开发均须遵循；本轮实现和验证仅覆盖 macOS；Windows 的网络边界于 2026-10-29 在 feature/windows-update-boundary 对齐（见下文「网络边界」中的 [Windows]），系统设置与账号／日志交互待后续分支。

### 系统设置

六个分类均可操作；控件使用 AppKit 原生目标／动作，保留水墨视觉。修改先进入草稿，保存后写入启动器自己的 `NSUserDefaults` 中 `localSettings`；跨分类保留草稿，撤销恢复已保存值，退出前提示未保存更改。类型和可选值按白名单校验，异常值回落默认，不接受任意路径／命令／地址。

| 分类 | 行为 |
|---|---|
| 常规设置 | 关闭窗口继续运行（默认开）、菜单栏图标（默认开）、辅助功能状态与系统设置入口。关闭继续运行后，最后一个窗口关闭即退出启动器，Claude 仍运行。 |
| 启动行为 | macOS 13+ 通过 SMAppService 管理本启动器登录项，操作单独确认且立即生效；仅接受标准应用程序安装路径，开发副本拒绝注册。macOS 12 提供用户与群组设置入口。恢复上次启动器页面（默认关）、默认页面（实例管理）、本地进程刷新间隔（1／3／5 秒，默认 1 秒）、点击指定账号时恢复最小化窗口（默认开）。绝不自动启动／恢复 Claude。 |
| 外观设置 | 显示水墨插画（默认开）、显示本地界面用量（默认开）。关闭用量显示后停止后续界面读取与通知监听、清空显示缓存；已在进行的只读任务可完成，但结果被丢弃。语言为简体中文、主题为浅色的固定说明，不提供虚假的语言／主题／浏览器选项。 |
| 数据与存储 | 显示／复制启动器数据目录，导出已保存偏好为 version 1 JSON，内存日志上限 100／500／1000（默认 500）。不导出账号、别名、项目、凭据。恢复默认只填入草稿，不清除别名、项目、登录保护、登录项或任何 Claude 数据。 |
| 消息通知 | 启动器窗口内警告提示（默认开）、系统提示音（默认关）、按已保存设置测试。不开启推送，不读取 Claude 消息。安全确认与错误弹窗不受通知开关控制。 |
| 关于软件 | 版本、离线使用帮助、复制基础诊断（仅版本／系统版本／辅助功能状态／联网开关）、手动更新开关与检查按钮。 |

不再提供自动恢复 Claude 实例、改默认浏览器、迁移账号目录或未存在的批量启动间隔。默认页面只在「恢复上次页面」关闭时可选。设置保存不修改运行中 Claude 的配置。

**[Windows]**（2026-10-29，feature/windows-settings）同一六分类与草稿规则，WPF 原生控件（开关为带切换状态的复选框，选项为下拉框）：

- 存储：`%LOCALAPPDATA%\Claude-MultiLauncher\settings.json`，`{"version":1,"closeToBackground":true,"showTray":true,"rememberPage":false,"startPage":"instances","refreshInterval":3,"restoreMinimized":true,"showArtwork":true,"logLimit":500,"localNotifications":true,"notificationSound":false,"allowUpdates":false}`。逐项按类型与可选值校验，单项异常只回落该项；文件缺失、损坏或版本不是 1 时全部用默认。同目录临时文件写完后替换；保存失败保留原文件与草稿。`startPage` 存页面名（`instances`／`accounts`／`logs`／`settings`，项目页接入后加 `projects`），不存序号。上次页面只在开启「恢复上次页面」时写入同目录 `last-page`。
- 常规：关闭窗口继续运行（开：隐藏窗口，托盘或再次打开启动器可恢复；关：关闭窗口即退出启动器，Claude 继续运行）；通知区域图标（关闭后托盘菜单不可用，再次打开启动器即可显示窗口）。
- 启动行为：开机启动写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `ClaudeMultiLauncher` 值（带引号的程序路径），单独确认、立即生效、不进草稿；只在程序位于 `%LOCALAPPDATA%\Programs\Claude 多开启动器\ClaudeLauncher.exe` 时允许开启，开发副本拒绝；关闭只删除本值且仅当它指向本启动器。卸载程序不处理该值（升级时 Setup 会先运行旧卸载程序，处理它会丢失用户选择），卸载前请先关闭开机启动。**[Windows 差异]** 本地进程刷新间隔默认 3 秒（实测一次 WMI 扫描约 280 ms，1 秒间隔开销过大），可选 1／3／5 秒。点击账号时恢复最小化窗口：关闭时若目标窗口已最小化，不还原、不切换，只提示从任务栏打开。
- 外观：显示水墨插画（侧栏山水、主区背景、账号卡片插画）。「显示本地界面用量」在本地界面用量实现前不提供开关，只显示说明；语言／主题为固定说明。
- 数据与存储：在资源管理器中显示、复制启动器数据目录；导出已保存设置为 `{"version":1,"settings":{…}}`（不含账号、别名、项目、凭据、登录保护、上次页面）；内存日志上限 100／500／1000（默认 500），保存后立即截断。
- 消息通知：窗口内提示为主区底部的临时提示条（约 5 秒），用于警告与错误；提示音用系统“感叹号”声音，仅在窗口内提示开启时生效；测试按钮按已保存设置显示。安全确认与错误弹窗不受影响。
- 关于软件：版本、离线帮助、复制基础诊断（仅启动器版本、Windows 版本、联网更新开关、Claude/Anthropic 请求禁止）、更新开关与检查按钮。
- 退出启动器（托盘「退出启动器」、关闭窗口且未开启继续运行）时有未保存设置：提示保存后退出／放弃更改退出／取消。系统注销或安装程序请求退出时不阻拦。

### 账号与日志交互

- 账号搜索支持本地别名、固定编号和目录；状态筛选支持运行中／未运行／处理中／异常。进程扫描失败时显示未知，不伪装成确定状态。统计仍按全部已有账号计算。
- 铅笔按钮设置最多 24 字的本地别名，去除首尾空白，拒绝控制字符；留空恢复默认。仅写 `accountDisplayNames`，不更改邮箱、身份或目录。实例卡片与账号表同步显示，编号始终保留。
- 原生复选框支持全选当前结果和部分选中；「复制选中路径」只复制当前可见选择。筛选隐藏的选择会清除，避免误操作。没有批量删除或自动批量启动。
- 日志支持本次运行／最近 5 分钟／最近 1 小时、实例、级别、全文搜索的组合筛选；每页 10 条，上一页／下一页根据结果启停。空结果有说明。全文可选择复制，截断单元格有完整提示。
- 导出写出全部筛选结果，非仅当前页；清空需确认，只清启动器内存。日志不持久化，按设置限制数量，退出即清空。确认弹窗与文件选择由用户决定。

**[Windows]**（2026-10-29，feature/windows-accounts-logs）同一规则，WPF 原生控件：

- 别名保存在 `%LOCALAPPDATA%\Claude-MultiLauncher\account-names.json`（`{"version":1,"names":{"2":"工作"}}`，键为 1～10，原子替换写入；损坏或版本不符时不显示别名、也不覆盖原文件，提示用户）。卡片与账号表显示“别名 · NN”，无别名显示“账号 NN”，圆形编号始终保留。托盘菜单仍只显示编号与状态。别名不进入设置导出。
- 搜索匹配别名、“账号 NN”、编号（含不补零形式）、目录路径，不区分大小写。状态筛选：全部／运行中／未运行／处理中（检查或启动中）／异常（失败、删除未完成）；进程扫描失败时状态显示“未知”，只在“全部”中出现。统计卡按全部账号计算。
- 表头复选框：全选当前结果，部分选中时显示中间态；“复制选中路径”把当前可见且选中的账号目录逐行复制到剪贴板。筛选或账号消失时清除不可见的选择。
- 日志：时间（本次运行／最近 5 分钟／最近 1 小时）、实例（全部／系统／Claude 1～10）、级别（全部／信息／警告／错误）、全文搜索（时间、级别、实例、内容，不区分大小写）组合筛选；每页 10 条，上一页／下一页按结果启停，显示“第 x / y 页”；事件内容为只读可选择文本，截断时悬停显示全文。空结果区分“暂无日志”与“没有符合条件的日志”。导出为 UTF-8 文本，写出全部筛选结果（按时间正序）；清空需确认。

### 网络边界

- 不再启动后检查、不设更新定时器。默认关闭 `allowUpdates`；需在设置中保存开启，再主动点击检查。
- macOS 不再注入／读取 UPDATE_BASE_URL 或自建服务地址。初始请求只允许 HTTPS、本项目 GitHub `latest/download/latest-macos.json` 与严格版本文件名的 DMG。拒绝用户信息、非 443 端口、其他仓库、任意路径及域名伪装。
- 重定向只允许本项目 Release 下载路径及 GitHub 的 `objects.githubusercontent.com`／`release-assets.githubusercontent.com`；拒绝所有其他域名，包括 Claude／Anthropic。使用无 Cookie、无凭据存储、无 URL 缓存的临时会话。签名、哈希、版本和安装证书校验保留。
- `--update-test` 也需明确的 `--allow-updates` 参数，且仍经过同一 URL 白名单；普通自检和 UI 自检不联网。导出、诊断、帮助不产生网络请求。
- 有未保存设置时不开始更新；下载期间若出现未保存更改，安装前取消并清理临时更新文件，保留当前程序和草稿。
- **[Windows]** `allowUpdates` 保存在 `%LOCALAPPDATA%\Claude-MultiLauncher\settings.json`（格式见上文「系统设置」[Windows]；缺失、损坏或类型不符按默认关闭）。「关于软件」中的“检查启动器更新”开关先进入草稿，点“保存设置”才生效。开启后每次打开启动器检查一次（只在有新版时提示，失败只记日志），另可从设置页或托盘“检查更新…”手动检查；未开启时这些入口都不联网，只提示先开启并保存。删除自建来源、取较高版本、启动 8 秒后／24 小时自动检查及 `last-update-check` 记录。
- **[Windows]** 唯一网络入口 `Updates.UrlAllowed` 在创建请求前校验：首次请求只允许 `https://github.com/wyl20020808/ClaudeLauncher/releases/latest/download/` 下的 `latest-windows.json` 与严格版本文件名的 `ClaudeLauncherSetup-<x.y.z>.exe`；跳转只允许同仓库 `releases/download/<标签>/` 下的这两类文件，以及 `objects.githubusercontent.com`／`release-assets.githubusercontent.com`。一律 HTTPS、443、无用户信息，最多 5 跳；请求不带凭据、不预认证、无 Cookie、不缓存，TLS 证书校验保持系统默认。发布脚本与自建服务过渡期仍为 1.7.3 及更早客户端发布，客户端不再读取。


macOS（`src/main.m`）和 Windows（`windows/`）各自原生实现，共同遵守本规格。macOS 1.6 是参考实现；规格变化时两端同步修改并在 STATUS 记录。

2026-10-28 隔离加固先在 macOS 实现；同日 Windows 在 feature/windows-sync 对齐（自检通过，GUI 与真实实例未验收，见 `windows/README.md`）。下文 [Windows 差异] 为平台原因无法逐字对齐之处。

## 账号与目录

| 编号 | 数据目录 | Claude Code 配置 |
|------|----------|------------------|
| 01 | 官方默认 userData（位置由平台和安装方式决定），不传覆盖参数 | 官方默认（`~/.claude`） |
| 02 | `<基础目录>/Claude-Second` | `<数据目录>/ClaudeCodeConfig` |
| 03～10 | `<基础目录>/Claude-Profile-NN` | `<数据目录>/ClaudeCodeConfig` |

- 基础目录：macOS 为 `~/Library/Application Support`；Windows 为 `%APPDATA%`（沿用已有 02/03 数据）。
  - **[Windows 差异，已确认]** MSIX 版 01 的默认 userData 实测为 `%LOCALAPPDATA%\Claude-Data\claude_pzs8sxrjxfjjc`，不在基础目录下；商店版还可能把目录虚拟化到 `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\<名称>`，Windows 端按同一账号识别和校验。见 `windows/README.md`。
- 02～10 启动参数 `--user-data-dir=<数据目录>`，环境变量 `CLAUDE_CONFIG_DIR=<数据目录>/ClaudeCodeConfig`。
- 界面只显示本机已有的账号（数据目录存在、正在运行或正在启动），按编号紧凑排列；没有任何账号时显示空状态提示。“新建实例”创建 01～10 中编号最小的未使用账号。编号与目录映射不变。
- 已有目录直接复用，不迁移、删除、覆盖、修改权限。新目录仅本人可访问。
  - **[Windows 差异，已确认]** 不设置 ACL，新目录继承 `%APPDATA%` 默认权限（本人、SYSTEM、Administrators），与“仅本人可访问”意图一致。
- 01 的子进程环境不得带 `CLAUDE_CONFIG_DIR`。Windows 用 `UseShellExecute=false` 会继承启动器环境，因此须显式移除；macOS 经 LaunchServices 启动，不继承启动器环境，只附加显式设置的变量，无需处理。

### Code 配置状态（两端）

- 01 显示“Code 默认”，仍与普通终端 Claude Code CLI 共用默认用户配置。
- 02～10 未运行显示“Code 待启动”；已运行但启动来源未确认显示“Code 未确认”。已有目录、正在运行和旧版启动记录均不能证明独立配置已生效。
- 仅本次启动器通过 LaunchServices 指定 `CLAUDE_CONFIG_DIR`，返回一个启动时间不早于请求时间、且主程序路径和账号参数匹配的新进程时，记录该进程对象。后续扫描仍为同一存活进程才显示“Code 已指定”。这仅表示启动参数已指定，不能宣称 Code 实际存储已验证。
  - **[Windows 差异]** 以 `Process.Start` 返回的 PID 记录，扫描到该账号唯一主进程为同一 PID、且 WMI `CreationDate` 不早于请求时间才显示“Code 已指定”；进程退出、PID 变化或重复主进程后清除记录。官方程序若转交给其他进程，PID 不匹配，保守显示“Code 未确认”。
- 不读取进程环境变量；记录仅在内存中保留。启动器重启、目标退出、PID 改变或重复主进程时，不能继续沿用已指定状态。旧实例由用户保存工作并正常退出后重新启动，不自动重启，不迁移旧配置或历史记录。

### 登录保护（两端）

- “···”菜单提供“登录 / 重新登录保护…”。首次创建账号空间时弹出提醒，用户选择“直接创建”或“进入登录保护”，不强制保护。
- 进入前与确认后重新扫描：其他管理/未管理的官方主进程、目标重复主进程、其他账号正在检查或启动、任何扫描错误都阻止进入。不会退出、登出或强杀任何实例。
- 保护账号编号保存在启动器自身偏好中，重开启动器仍保留。保护期间不允许通过启动器打开其他账号、新建实例或删除受保护账号；目标检查和启动仍可正常完成。
- 用户自行完成登录或取消浏览器登录流程，再确认“结束保护”。存在检查或启动操作时暂不允许结束，避免后台操作跨越保护状态。
- 保护不截获回调、不读取身份，不能约束 Dock、终端等外部启动。发现外部实例时持续提示停止登录；不能保证回调一定属于目标账号。
  - **[Windows 差异]** 保护编号保存在 `%LOCALAPPDATA%\Claude-MultiLauncher\login-protection`；外部入口为开始菜单、任务栏、终端等。

## 进程识别

- 只认官方主程序路径；排除 Helper、GPU、renderer（参数含 `--type`）以及 Claude Code CLI。
- 从系统读取命令行参数解析 `--user-data-dir`（支持 `=` 与空格两种形式）：无参数为 01；重复参数、相对路径或缺值视为无法识别并暂停操作；不在 01～10 内的目录记为未管理实例。
- 不读取进程环境变量（可能含凭据）。
- 任何官方实例无法核对参数时，暂停启动，不重复启动、不结束进程。

## 启动与激活

- 运行中：按 PID 激活。激活前再次核对该 PID 的路径和账号；不以按程序名打开代替。
  - **[Windows 例外，已确认]** 主进程在托盘中、按 PID 找不到可见窗口时，允许用同一 `--user-data-dir` 再启动一次，由 Claude 单实例锁（4.29 含 `requestSingleInstanceLock`，按 userData 区分）转交已有进程显示窗口。必须同时满足：该账号恰好一个已核实主进程且无可见窗口；使用该 PID 的可执行文件；之后重新扫描，若同账号出现第二个主进程则报错，不结束任何进程。macOS 保持纯 PID 激活，最小化窗口经辅助功能恢复。
- 同一账号多个主进程：报错，不激活、不结束任何实例。
- 未运行：校验存储后以新实例启动；启动中禁用按钮防重入，35 秒未出现主进程报失败。
- 启动器单实例；再次打开时唤起已有窗口。关闭启动器不退出 Claude。
- 递归存储检查放到后台，不占用界面主线程；同账号检查期间禁止重复打开/删除。不同账号可独立检查，失败只记录在该账号。完成后重新扫描进程、检查保护状态及根目录元数据。原本要激活的 PID 若退出或被替换，不自动重启，也不静默切换到另一个 PID。删除同样在后台检查完成后再扫描和校验路径。
- **[macOS]** LaunchServices 请求超过 35 秒仍未回调时报告超时，但继续保留该账号的启动中状态，禁止重试及其他账号进入登录保护，直到系统返回。不会强制结束启动请求或 Claude。
  - **[Windows 差异]** `Process.Start` 为同步调用，立即返回 PID 或失败，不存在悬挂的启动请求；35 秒超时只用于等待主进程窗口出现。
- 无法识别的官方进程仍触发全局暂停；这是防止重复启动的保护，不因降低耦合而取消。

## 存储校验

只检查元数据，从不读取内容。目录及各级上级不得为链接或非目录；以下存储项不得为链接、非本人所有、普通文件硬链接：
`Cookies`、`Cookies-journal`、`Network`、`Local Storage`、`Session Storage`、`IndexedDB`、`Partitions`、`Local State`、`Preferences`、`config.json`、`Cache`、`Code Cache`、`Service Worker`、`ClaudeCodeConfig`。

Windows 对应：重解析点（符号链接、junction）等同链接；硬链接数通过文件信息查询。所有者按 ACL 所有者 SID 判断，以管理员身份创建的文件属于 Administrators 组，会被拒绝。

## 项目清单

先在 macOS 实现，Windows 端以后按同一规格实现。项目目录本来就由同一 macOS 用户下的所有账号共享；公共清单只是统一入口，不复制、不同步、不合并任何项目内容或会话。清单只存在本机，不跨电脑同步。可选的原生侧栏目录登记见下文，独立于只读识别与公共清单导入。

### 共享的取舍

- 所有账号引用同一个真实目录，因此项目中的代码、文档、`CLAUDE.md`、`.claude/settings*.json`、`.mcp.json` 都会被使用该项目的账号共同读写。项目级配置共享与“账号尽量隔离”方向相反，这是用户为了方便主动选择的取舍；账号登录、内部会话和用户配置目录仍独立。
- 同一项目请轮流使用。启动器无法检测多个实例同时编辑，也不提供文件锁、冲突检测或合并。

### 界面与操作

- 左侧新增“项目管理”，顺序为实例管理、账号管理、项目管理、日志记录、系统设置。沿用表格样式，列为名称、分组、路径、状态（正常／不存在／无权限）、上次使用账号、操作。
- 清单全局共享，不建立账号与项目绑定。任何账号均可打开任何项目，只记录上次使用的账号编号作为下次选择的默认值；未使用时为空。
- 保留通过 `NSOpenPanel` 选择已有文件夹；支持修改名称、分组、上移／下移排序、在 Finder 显示、复制路径和移除记录。移除绝不删除或移动实际目录及文件。
- “用账号打开”选择账号后复用 `selectAccount` 的完整流程（PID 核对、登录保护、后台存储检查及启动防重入）。通过检查并请求激活／启动目标账号时，复制项目路径到剪贴板、在 Finder 显示目录，提示“请在 Claude 中选择此文件夹”。记录的是最近通过检查并发起的账号操作，不代表 Claude 已加载项目。检查失败或用户取消时不更新此记录、不执行路径交接。
- 不使用 `claude://`、不使用 `open -a` 打开文件夹，不改账号数据。官方 4.29 的只读调查未发现“打开文件夹到指定实例”的可靠入口，`claude://` 可能交给任意实例，因此实际选取目录由用户完成。

### 一键识别与导入（macOS）

- “识别并导入”检查全部已创建的 01～10 账号空间，包括未运行的账号。读取范围固定为各账号的 `claude-code-sessions/<账号 UUID>/<组织 UUID>/local_<UUID>.json`，包括仍保留在本机的历史／归档记录；不递归扫描磁盘，不要求 Claude 正在运行。
- 依据官方 4.29 的序列化格式，只逐字节读取记录开头的 `sessionId`、可选 `cliSessionId`、`cwd`、`originCwd` 字符串；优先使用非空 `originCwd`。读完立即停止，绝不预读后面的会话正文、配置或凭据。键顺序／类型不匹配就跳过；不打开其他 JSON、JSONL、浏览器数据库、CLI 配置或日志。不会复制、修改或写回任何客户端记录。
- 这是目录候选识别，不是官方项目清单接口，不能保证历史项目完整。已删除记录、旧／未知格式、额外工作目录、云端项目及没有目录记录的项目不在覆盖范围。路径字段也不能证明记录来自本地会话：本机恰好存在同名远程路径时，需用户在预览中核对。不会自动将工作目录推断成仓库根目录。
- 目录逐层以 `openat` 和 `O_NOFOLLOW` 打开，拒绝链接、非当前用户的源目录／文件、硬链接源文件和可被其他用户写入的源。固定三层枚举，最多检查 20000 个目录项／5000 份记录，单份前缀最多 32768 字节；达到上限明确报告，不能宣称全部完成。
- 后台识别完成后显示可勾选的候选目录、来源账号及逐账号结果。先复用已有路径准入检查，再按真实目录身份去重。已存在项目保留名称、分组、顺序和上次账号；新增项追加到末尾，上次账号为空。主目录、根目录和系统临时目录不批量导入，需走原来的手动添加流程。
- 确认导入时再次校验路径和重复情况，批量原子保存；取消不写入。缺失／无权限／受保护路径、格式不支持、读取失败分别计数；没有候选只表示此次没有识别到，不表示没有项目。清单容量不足或保存失败时整批不写入。
- 全过程仅在本机执行，不请求 Claude 官方接口，不启动、退出或激活客户端，不操作剪贴板／Finder，不改变隔离机制。这里的“同步”仅指向启动器公共清单汇总目录入口，不同步文件、会话或 Claude 原生侧边栏。

### 原生侧栏目标与探索记录

用户追加的目标是：汇总全部已创建账号的本地项目目录后，让未使用过这些目录的账号，也能在 Claude 自身左侧看到对应入口，并在该目录中新建自己的独立对话。这与已发布的“导入启动器公共清单”不同；现有导入功能继续保留。

- 只允许本机目录登记，不调用 Claude 云端项目／会话接口，不同步会话、消息、账号身份、登录状态、环境变量或权限配置。
- 验收必须在目标客户端实际看到入口，并确认新对话草稿指向正确目录。写入配置成功、启动器显示成功、Claude 的环境选择器显示成功，都不能替代原生侧栏验收。
- Claude 4.29.0 第一阶段 GUI 验证未通过上述目标：保存本地环境、开启空分组、切换为按环境分组，都没有为从未创建会话的测试目录生成侧栏入口。对应文件与缓存机制见 [本地侧栏调查](SIDEBAR-LOCAL-RESEARCH.md)。
- 不复制数据库或修改官方应用；未通过实际验收的路径不能宣称已完成。用户授权空归档记录实验及后续接入的具体边界见下文。

用户随后授权受控验证“去掉会话内容后能否保留目录分组”。验证必须从目录路径白名单重新生成记录，不能先复制真实会话再删字段。每个目标使用全新 `local_<UUID>`，仅保留 `sessionId`、`cwd`、`originCwd`、测试标题、新时间戳和 `isArchived`；不带任何 CLI／历史／云端 ID、恢复任务、消息、MCP、环境、权限或账号字段。先用合成数据离线验证，再在用户已正常退出的单一目标账号中独占新建一条测试记录，不覆盖任何现有文件；真实 GUI 验证与离线检查分开报告，验证后清理。此项为第一阶段只读调查之后的明确实验授权；该实验本身不代表批量功能已交付。

第二阶段实验结果：在 Claude 4.29.0 中，`isArchived=true` 的全新空记录配合“显示空分组”，可以生成原生侧栏目录入口，显示“无活跃会话”；正常重启后保留。点击新建会话能准确进入该目录的信任确认；该次实验取消确认，没有授予目录信任或发送消息。删除唯一实验记录并重启后，分组消失。此方案需要长期保留空归档记录，不能把记录文件全部删除后仍宣称目录已登记；详情见调查报告的第二阶段。该阶段尚未实现批量应用与去重；后续产品接入及真实目录验收见下节。撤销、升级兼容和长期清理策略仍未完成。

### 登记到 Claude 侧栏（macOS）

- 保留手动添加与只读识别导入。新增“登记到账号”，从公共清单勾选目录并选择一个已创建的目标账号；一次可登记多个目录，不复制真实会话文件。目标须正常退出且不处于启动、检查或登录保护状态。源账号是否运行不影响目录前缀识别。
- 当前仅允许已验证的官方 Claude 4.29.0。目标 `claude-code-sessions` 下必须只有一个可安全访问的账号 UUID／组织 UUID 位置；缺失、多位置、链接、权限或格式异常时拒绝写入，不创建、猜测或复制身份目录。
- 仅生成七字段：全新 `sessionId=local_<UUID>`、真实 `cwd`／`originCwd`、固定标题“项目目录入口（无对话）”、新建时间、最近活动时间、`isArchived=true`。不复制来源名称、会话 ID、消息、权限、环境、MCP、Cookie 或凭据。每个目标生成独立 ID。
- 复用项目路径准入规则，批量拒绝主目录、根目录及系统临时目录。目标已有同目录记录时跳过；只读记录前缀，不解析后续内容。目标扫描上限为 5000 条记录／20000 个目录项，遇到不完整读取或未知记录前缀时拒绝登记，避免误判重复。
- 新记录 0600；同目录独占临时文件写完并 fsync 后，以不覆盖模式原子发布。每次发布前重新核对目标路径身份、目录状态及进程。成功部分不回滚删除，后续失败明确报告已添加和跳过数量，重试去重。启动器不能拦截从外部入口启动 Claude，因此操作期间不要从 Dock 或终端打开目标账号。
- 完成后由用户启动目标账号，在 Claude 的“分组和排序 → 显示 → 空分组”开启显示。启动器不编辑客户端浏览器数据库，不自动授予目录信任。目录会在侧栏显示“无活跃会话”，新会话仍走官方目录信任与账号自身设置。
- 空归档记录需保留，可能在归档列表中可见；移除启动器清单记录不删除客户端记录。第一版不提供批量撤销，不删除或覆盖任何已有会话。未来 Claude 更新、自动清理和长期保留仍需重新验证。
- 开发诊断 `--register-projects-from <源编号> <目标编号>` 仅预览计数；显式追加 `--apply` 才写入，复用相同版本、保护、进程、路径、存储及去重检查。此入口只从源账号记录前缀取得目录，绝不输出原始记录内容。

2026-10-28 实测：01 的三个真实目录以全新空归档登记到 02，侧栏出现对应分组且正常重启后保留；一个已信任目录的新草稿路径正确，另外两个进入对应目录的信任提示后取消。没有发送消息。原有目标记录元数据在登记前后保持不变，命令行和 GUI 重复登记均跳过三个已有目录。完整验收与限制见 STATUS。

### 公共清单存储与路径安全

- 保存位置：`~/Library/Application Support/Claude Launcher/projects.json`。格式为 `{"version":1,"projects":[{"id":"UUID","name":"名称","group":"分组","path":"绝对真实路径","lastAccount":0}]}`；数组顺序即显示顺序，`lastAccount` 为 0（未使用）或 1～10。
- 新文件权限为 0600，同目录临时文件写完后原子替换。清单只保存上述元数据，不包含登录信息或项目文件内容。写入失败保留之前的清单和界面数据。
- JSON 损坏或结构非法时提示用户，把原文件改名为同目录的 `projects.json.corrupt-<UUID>` 保留，不覆盖原始内容；保留失败或遇到不安全的存储路径时停止写入并提示。未知版本保留原文件并停止写入，避免覆盖未来版本的数据。
- 项目路径必须为绝对路径，添加时标准化并解析为真实目录。拒绝账号数据目录（`Claude`、`Claude-Second`、`Claude-Profile-NN`）及其子目录、路径中包含 `ClaudeCodeConfig` 的目录、启动器自己的数据目录及应用包。别名指向这些位置同样拒绝；重复真实路径不重复添加。
- 添加用户主目录或根目录需要额外确认。只检查目录元数据和可访问性，不读取项目文件内容；不要求目录可写，允许只读项目。
- 已记录路径不存在、不是目录或已指向其他位置时标记“不存在”；无读取／遍历权限时标记“无权限”。不自动新建、不迁移、不替换路径；打开前重新校验，失效或变为受保护路径时拒绝交接。父目录授权可能涉及系统隐私提示，由用户自行决定，启动器不修改系统权限。

### 验证

- 合成自检覆盖路径准入及链接绕过、重复路径、清单读写往返与 0600 权限、损坏文件保留、未知版本不覆盖、移除记录不删除项目文件；只用随机合成目录并清理。
- 使用 `--snapshot` 离屏检查项目页（页码 2），分别检查空清单和合成项目行。截图不读取真实清单、不启动 Claude；GUI 点击和账号交接另行报告，未执行项标为“未验证”。

## 本地界面用量（macOS）

- macOS 1.7.9 起，只读官方 Claude Code 已显示的用量控件。Windows 未接入。`UsageHistory.m` 留作历史实现，不再编译或调用；不再读取 `plan-usage-history.json` 或访问 Claude Safe Storage，也不回退到旧历史。仅为缓存归属定向读取已获授权的非登录 `lastActiveOrg` 字段并生成 SHA-256 指纹，不读取登录字段、不解密。
- 先用官方主进程可执行路径、内核启动参数及固定账号目录定位 PID，排除 Helper、GPU、renderer、CLI 和未管理进程。同账号多个主进程、路径异常或进程扫描失败时不显示数值。读取前后重核 PID、进程启动时间、目录身份和组织选择指纹；读取后再扫描进程，异步返回时复核。Cookies／journal／wal／shm 元数据变化仅触发组织字段重新核对，普通 Cookie 写入不会清空观察记录。固定查询只选官方域名、根路径、未过期的 lastActiveOrg；schema 24 / v10、只读 immutable、不复制、不建锁或日志，拒绝 WAL、活动日志、歧义及读取期间的变化。只保留指纹，既不保存原值也不访问钥匙串。元数据未变时复用指纹最多 60 秒；它不证明服务器身份或尚未落盘的组织切换。
- 只通过系统辅助功能复制现有 AX 属性，不执行动作、不激活 Claude、不设置官方界面属性、不启用调试或增强辅助功能开关。需要用户已经授予启动器的辅助功能权限；没有权限就显示“需辅助功能权限”，不自动弹出授权或改 TCC。固定签名身份不变。
- 限定官方 `https://claude.ai/epitaxy/…` Code 页面，拒绝嵌套浏览器页面。仅解析用量弹出按钮和相邻、带官方用量设置链接的面板；读取五小时及“每周 · 所有模型”，不将上下文 token 百分比或模型专属周限额混入。文本正文、输入框内容不读取。多个用量页面、重复或矛盾指标、遍历预算耗尽、未知格式均不采用新的不确定结果。
- macOS 1.7.10 起，只有打开／恢复启动器并进入实例页、实例页重新获得焦点、返回实例页、或在该页点击才读取一次；1 秒内重复焦点／点击合并。窗口内鼠标抬起通过本应用的本地事件监视器观察，不监听其他应用输入，不消费或合成事件。持续停留、后台、其他页面、Claude 界面变化及原进程刷新定时器都不得触发用量控件读取或组织指纹核对。已开始的一次读取可完成；进程状态定时器继续只做原有状态管理和缓存显示，进程退出／变化时隐藏旧值。
- 五小时按钮在弹窗关闭时可提供数值；周限额只在用户主动查看启动器触发读取时，官方节点已经可读才取得。启动器不会代为展开，也不承诺捕获每次短暂出现的弹窗。首次未观察到周限额显示“—／尚未观察到”。此限制不能用历史、推算或额外查询补齐。
- 两项各有独立观察时间。当前读取显示“读取于 HH:mm:ss”；周控件关闭后，只有账号、进程及组织指纹一致才可保留最近观察值，并标“上次显示 HH:mm:ss”（跨日带日期）。五小时的新读取不会刷新周限额时间。悬停可看完整日期及官方原始重置说明；不推算重置、不将观察时间当作服务器采样时间。
- 用户要求记录最近查看结果：仅把两项百分比、重置说明、各自观察时间和用于匹配的进程／目录元数据及组织指纹保存到启动器自己的 `usageInterfaceObservations` 偏好，不存页面／会话标识、正文或凭据，不写官方目录。重启启动器先校验记录格式和时间，再匹配当前主进程、目录和组织指纹后恢复，均标“上次显示”。同账号切换 Code 对话或关闭弹窗不会丢失已观察值；界面暂时不可读可继续显示已验证归属的最近观察值。账号／PID／进程启动时间／目录／组织指纹确认改变时清除；登录保护、进程歧义、权限丢失或身份文件写入中则隐藏，后续身份一致时恢复。关闭显示设置清空缓存。设置沿用旧 `showUsageHistory` 键以保持开关选择，名称改为“显示本地界面用量”。
- 每次读取最多 16000 次属性访问、1.5 秒预算；只处理 40 层内的用量布局，更深分支跳过（不是用量候选），重复结构节点去重；普通节点只批量读取角色与子节点，单次系统 IPC 超时 0.1 秒；超时／读取中页面变化不采用新结果。不注册 Claude 辅助功能通知，不调用任何官方查询 IPC 或认证提供器。
- `--usage-interface-check` 只输出账号编号、读取状态、两项是否观察到及耗时；不输出百分比、页面会话标识或正文。从终端执行时权限归属可能与 GUI 启动不同，不据此自动修改授权。GUI、合成自检和离屏渲染分开报告。旧 `--usage-history-check` 已移除。限制与研究证据见 [用量调查](USAGE-RESEARCH.md)。

## 更新与安装

> **Windows 已实现（1.7.0 起，2026-10-29 按「网络边界」收紧）**：`latest-windows.json` 验签、仅 GitHub 来源、集中 URL 白名单、只升不降、`minimumOS` 判断、下载后大小/SHA-256 核对（不符删除）、静默运行 Setup 并由 Setup 重新打开启动器；检查时机与开关见「网络边界」[Windows]。发布脚本 `windows/scripts/publish-release.ps1`（过渡期仍同步自建服务）。
>
> - **[Windows 差异]** 同一证书：当前 Windows 程序与 Setup 都没有 Authenticode 签名。程序已签名时要求 Setup 由同一证书签名且签名有效；当前程序未签名时无法比对签名者，只依赖清单 RSA 签名与 SHA-256。取得代码签名证书后此限制自动消失。
> - **[Windows 差异]** 回滚：Setup 先卸载旧版再安装，新版安装失败时旧版已卸载，无法自动回滚到旧版（账号数据不受影响，可重新运行 Setup 或从 GitHub 下载）。旧版卸载失败、启动器无法正常关闭时则中止并保留旧版。
> - **[Windows 差异]** `minimumOS` 每段允许 1～5 位数字（Windows 版本号第三段为构建号，如 `19041`）。macOS 端解析 `latest-macos.json` 时可保持 1～3 位。
> - 兼容 1.2.0：发布脚本额外签发旧格式 `latest.json`（签名原文 version、file、size、sha256），指向同版本的单个 `ClaudeLauncher-x.x.x.0.exe`，1.2.0 客户端用 `--apply-update` 原地替换；新程序保留该入口。旧清单只放自建服务。
> - 发布流程与上文的差别：macOS DMG 由 macOS 端先上传到草稿 Release，发布脚本下载并核对 macOS 给出的 size/sha256，再上传 Setup 与两份清单，切换自建服务清单后把草稿转为正式；正式发布后的任何失败都会恢复自建清单并把 Release 改回草稿。

两端共用一套发布与校验流程。来源有两个，内容相同、校验相同：放在哪里不影响安全，安全只靠签名。

### 版本

- 版本号格式 `主.次.修订`（如 `1.7.0`）。Windows 程序集版本写成 `1.7.0.0`，清单里仍写 `1.7.0`。
- 两端版本号各自递增，不要求一致（2026-10-28 用户决定）。客户端只读本平台清单，版本不同不影响更新。
- 只接受比当前更高的版本，不降级。

### 清单

每个平台一个清单：`latest-macos.json`、`latest-windows.json`。字段：

| 字段 | 说明 |
|------|------|
| `platform` | `macos` 或 `windows` |
| `version` | `1.7.0` |
| `file` | macOS：`ClaudeLauncher-1.7.0.dmg`；Windows：`ClaudeLauncherSetup-1.7.0.exe`。只用 ASCII：GitHub 会改写附件名中的非 ASCII 字符（实测 `Claude多开启动器-1.7.0.dmg` 变成 `Claude.-1.7.0.dmg`），回退下载会 404。 |
| `size` | 字节数，上限 50 MB |
| `sha256` | 小写十六进制 |
| `minimumOS` | macOS `12.0`；Windows `10.0.19041` |
| `signature` | Base64，RSA-3072 + SHA-256，对下面的签名原文签名 |

签名原文（UTF-8，每行以 `\n` 结尾，顺序固定）：`platform`、`version`、`file`、`size`（十进制）、`sha256`。

- 共用密钥：两端内置同一把公钥 `windows/assets/update-public-key.xml`；私钥只在 Windows 发布机（DPAPI 保护），不进仓库、不出现在日志。
- macOS 独立密钥（2026-10-28 用户同意，1.7.4 起内置）：Mac 发布机生成自己的 RSA-3072 私钥，只存在该 Mac 的钥匙串，公钥以同样的 RSAKeyValue XML 提交为 `resources/update-public-key-macos.xml`。Mac 客户端对 `latest-macos.json` 接受共用公钥或 Mac 公钥任一验签通过。过渡版（第一个内置 Mac 公钥的版本）仍由 Windows 发布机用共用密钥签名；之后 Mac 版本由 Mac 发布机自行签名发布。Windows 清单只认共用密钥。
  - 【macOS 差异】包内文件名为 `macos-publisher-key.xml`：NSBundle 把以 `-macos` 结尾的资源当作平台变体，会在查找 `update-public-key.xml` 时返回 `update-public-key-macos.xml`（实测），导致共用公钥加载不到。仓库路径仍为 `resources/update-public-key-macos.xml`。
  - Mac 私钥创建为不可导出（用户选择不备份），只能在生成它的这台 Mac 上签名。这台 Mac 丢失或重装时：由 Windows 发布机用共用密钥继续为 Mac 签名（1.7.4 起的客户端两把都认），或生成新的 Mac 密钥并随一个共用密钥签名的版本发布新公钥。
- 清单大于 16 KB、字段格式不符、文件名与版本不对应、签名无效，一律拒绝。下载后大小或 SHA-256 不符同样拒绝并删除临时文件。
- 兼容：在所有 1.2.0 客户端更新到新协议前，服务器继续提供旧的 `latest.json` 与 `ClaudeLauncher-x.x.x.x.exe`。

### 来源与回退

1. **GitHub Releases（唯一来源，2026-10-28 用户决定）**：`https://github.com/wyl20020808/ClaudeLauncher/releases/latest/download/latest-<平台>.json` 与同一 Release 中的安装包。自建更新服务不再作为客户端来源：macOS 自 1.7.8 起移除；Windows 于 feature/windows-update-boundary 移除（随下一个 Windows 版本发布）。此前的“自建优先、回退 GitHub”与 1.7.6 的“取较高版本”随之停用。
2. 取不到有效清单、验签失败或下载失败：提示原因，并提供“前往 GitHub 下载”按钮打开 Releases 页面，由用户手动下载安装。

检查时机：启动器每次打开时检查一次，以及用户手动点“检查更新”；不定时、不在后台重复。两者都只在设置中开启了更新时进行（默认关闭）。启动时的检查只在发现新版本时提示，失败只记日志。

只用 HTTPS，不跟随跳转到其他域名（GitHub 下载跳转到 `objects.githubusercontent.com`、`release-assets.githubusercontent.com` 除外），请求有超时与大小上限。

更新过程界面（两端）：确认“立即更新”后显示进度窗口，依次为“下载 → 校验 → 安装”。下载显示真实进度（已下载／总大小、百分比、来源），可取消，取消即删除临时文件、不做任何改动，关闭窗口视为取消；校验为不定进度，也可取消；校验通过后提示“启动器即将关闭，完成后会自动重新打开”，约 2 秒后退出并由替换步骤完成安装。不退出、不结束任何 Claude。

### 发布流程（发布机）

一个脚本完成：构建两端安装包 → 计算 SHA-256 → 用私钥签名两份清单 → 上传自建服务 → `gh release create v<版本>` 上传两份清单与两个安装包 → 两个来源各下载一次并验签核对。任何一步失败都不发布半成品。

**每个正式 Release 都必须同时包含两端当前的清单与安装包。** GitHub 回退地址 `releases/latest/download/` 只指向最新的一个 Release；若只放一个平台的文件，另一平台回退时会 404。

- 两端同时发布：标签 `v<版本>`。
- 只发布一个平台：标签 `windows-v<版本>` 或 `macos-v<版本>`，另一平台的清单与安装包从上一个最新 Release 原样带入（验签并核对哈希后再上传，不重新签名），自建服务中另一平台的清单不改。Windows 发布脚本已支持只发布 Windows；Mac 发布脚本同样从上一个最新 Release 带入 Windows 文件（已签名，无需私钥）。两端版本不要求一致，哪端有新功能哪端就发，另一端之后再跟上。只发布 macOS 时，自建服务由同步自动更新，不需要 Windows 发布机操作（Mac 独立密钥生效之后）。

### 安装：先卸载旧版，再装新版

通用规则：

- 只卸载**启动器程序本身**。**任何情况下都不删除账号数据目录**（macOS `~/Library/Application Support/Claude*`，Windows `%APPDATA%\Claude-*`、`Claude-Data` 等）、Code 配置或启动器偏好。
- 只正常退出**启动器**，不退出、不结束任何 Claude 实例。
- 先校验新包，校验通过才动旧版；新版装好并校验通过后才清理旧版，失败自动回滚到旧版。
- 新旧版本必须由同一证书签名，否则拒绝更新（避免授权失效和被替换成伪造程序）。

**Windows（Setup 安装程序）**

- 用固定 AppId 检测已安装版本（注册表卸载项）。已安装时：提示“检测到已安装 x.y.z，将先卸载再安装新版”，正常关闭运行中的启动器，静默运行旧版卸载程序，确认卸载完成后再安装新版。
- 旧版卸载失败则中止安装，保持旧版可用，并提示原因。
- 自动更新下载的就是这个 Setup，以静默参数运行，完成后重新启动启动器。

**macOS（应用内更新与 DMG）**

- 自动更新：下载 DMG → 校验 → 挂载 → 校验其中应用的签名要求与当前应用一致 → 正常退出启动器 → 把旧版改名为备份 → 复制新版到原位置 → 校验新版签名 → 成功后把备份移到废纸篓（即“卸载旧版”）并启动新版；任一步失败则删掉不完整的新版、恢复备份并启动旧版。
- 手动 DMG 安装：拖到“应用程序”时由系统提示“替换”，等同于先移除旧版再安装。DMG 内附一份简短说明。

## 常驻图标

启动器运行期间在系统常驻区域显示图标：macOS 为顶部菜单栏右侧，Windows 为任务栏通知区域（托盘）。关闭主窗口后启动器继续运行，图标仍在。

- 图标为占位图，后续替换为用户提供的图标（macOS 使用单色模板图，随菜单栏深浅色自动适配）。
- 单击（Windows 为左键单击或双击）打开菜单；菜单内容按此顺序：
  1. 显示启动器窗口
  2. 本机已有账号列表：`账号 NN · 运行中/未运行`。点击与界面中的主按钮相同（打开 / 启动），走同样的检查（PID 核对、登录保护、存储检查），不绕过任何规则。
  3. 检查更新…
  4. 退出启动器（只退出启动器，不退出任何 Claude）
- 菜单每次打开时重新扫描进程，不显示过期状态；扫描失败时账号项禁用并显示原因。
- 不在菜单中显示登录邮箱或任何账号内容。
- **[Windows 差异]** 按 Windows 托盘习惯：左键单击或双击显示主窗口，右键打开菜单（用户 2026-10-28 指定）。菜单中账号项与卡片同源，另会显示“检查中/启动中/删除未完成”等进行中状态；从托盘操作时主窗口若隐藏，确认框居中置顶显示。
- **[Windows 差异]** 关闭主窗口只隐藏到通知区域（首次提示一次）；安装程序改用专用窗口消息 `ClaudeMultiLauncher.Exit` 请求启动器退出，并同时发送 WM_CLOSE 兼容旧版本。再次打开启动器时通过命名事件通知已运行实例显示窗口。
- **[Windows]** 图标：`windows/assets/app.ico` 由 `resources/icon/icon_full_1024.png` 生成（`windows/scripts/make-icon.ps1`），含 16～256 共 8 个尺寸；16～24 像素为简化图形（橙色圆角方块 + 白色光芒），32 及以上为原图缩小。exe、Setup、窗口、托盘共用；官方图标 `claude.ico` 已从 windows/ 移除（仍存在于 Git 历史中）。

## 禁止事项

- 不修改、复制、重签官方 Claude 程序（仅可复制图标）。
- 不读取、复制、打印登录凭据；登录由用户完成。仅本地用量匹配按上文授权范围访问 Safe Storage 加密密钥，不能用于解密登录信息。
- 不强杀 Claude；不修改系统权限或安全设置。
- 不伪装设备指纹或网络出口。
- 删除账号（2026-10-28 用户要求恢复）：仅通过“···”菜单，二次确认后移到废纸篓（可恢复），不永久删除；01 默认目录不可删；运行中或启动中不可删；删除前重新扫描进程并校验路径。
  - **[Windows]** 已对齐：“···”菜单删除，回收站；01、运行中、启动中、检查中、登录保护中不可删；确认后重新扫描并校验路径。删除前任一会话中该目录的 Claude 进程（含辅助进程）都会阻止；同一账号的普通目录和 MSIX 虚拟化目录一并移入回收站。“删除未完成”的重试保留。
  - **[Windows 差异]** 1.2.0 中对 01 发起且未完成的删除，因 01 不可删而无法在启动器内重试，需用户手动处理标记文件；启动器不自动清除。

## 自检

每端提供 `--self-test`：账号映射、Code 配置映射唯一性、参数解析（含 Helper/CLI 排除、异常参数）、路径校验（链接、硬链接拒绝），只用随机合成目录并清理。

两端加固自检还覆盖：登录保护准入、进行中操作和删除互斥、检查期间 PID 退出/替换及保护状态变化、保守 Code 状态、并发元数据检查与主线程回调（macOS）、深层存储链接/硬链接与深层 Code 存储链接拒绝。自动检查不代替 GUI 或真实账号登录验收。

Windows 端的 `ClaudeLauncher.exe` 是 GUI 程序，需用 `ClaudeLauncher.exe --self-test | Write-Output` 运行，才会等待退出并显示结果。
