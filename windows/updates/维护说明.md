## 发布新版（SPEC 更新与安装）

1. 递增版本号（两端各自递增，不要求一致）：Windows 修改 `src/Updates.cs` 的 AssemblyVersion、AssemblyFileVersion、`Version`（x.y.z.0）和 `DisplayVersion`（x.y.z）。
2. 只发布 Windows：跳过本步。两端同时发布：macOS 端用 `scripts/dmg.sh` 生成 DMG，并用 `gh` 上传到草稿 Release `v<版本>`，同时给出 DMG 的 size 和 sha256。
3. 在 `windows/` 下运行：

   ```powershell
   # 只发布 Windows（标签 windows-v<版本>，macOS 文件从上一个最新 Release 带入）
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish-release.ps1
   # 两端同时发布（标签 v<版本>）
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish-release.ps1 -MacSize <字节数> -MacSha256 <小写哈希>
   ```

   每个正式 Release 都必须同时有两端的清单与安装包，因为 GitHub 回退只看最新的 Release。

   脚本依次：构建 Setup（含自动检查与自检）→ 从草稿下载 DMG 并核对 size/sha256 → 在内存中解密 DPAPI 私钥，签名 `latest-windows.json`、`latest-macos.json` 和 1.2.0 兼容 `latest.json` 并本地验签 → 把安装包复制到 `public/` → 上传 Setup 与两份清单到草稿 → 原子切换自建服务清单 → 草稿转正式 → 从自建服务和 GitHub 各下载一次验签并核对哈希。上传后先经 GitHub API 下载草稿附件逐字节核对（不符则停在草稿、原 Latest 与自建服务不变），转正式前记下上一版 Latest；只有内容确认不符才回滚（恢复自建清单、改回草稿并显式恢复上一版 Latest），latest/download 最多等 10 分钟，仅缓存未更新或自建服务暂时不可达时保留发布并以状态 2 退出。相同版本不得以不同内容重新发布。
4. 先用 `-DryRun`（可配合测试密钥与 `-MacDmg` 本地文件）在本机演练：只构建、签名、本地校验，不上传。

签名私钥保存在发布账户的 `%LOCALAPPDATA%\ClaudeLauncher-Publisher\signing-key.dpapi`。本机这份是在 Codex 桌面版（打包应用）里生成的，Windows 把写入重定向到了 `%LOCALAPPDATA%\Packages\OpenAI.Codex_2p2nqsd0c76g0\LocalCache\Local\ClaudeLauncher-Publisher\signing-key.dpapi`，`publish-release.ps1` 会自动找到它。注意：卸载或重置 Codex 应用会清掉这个包缓存，私钥随之丢失，备份方式需由用户决定。私钥由 Windows DPAPI CurrentUser 加密，只在内存中解密，不写明文、不进日志。不要复制到 `public/`、仓库或发给客户。`assets/update-public-key.xml`（RSA-3072）是公开校验密钥，两端客户端都内置它。不要重建密钥，否则旧客户端无法接受新包；迁移发布电脑必须专门处理密钥迁移，单纯复制 DPAPI 文件不能保证解密。
