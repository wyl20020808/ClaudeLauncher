## 发布新版（SPEC 更新与安装）

1. 两端统一版本号：Windows 修改 `src/Updates.cs` 的 AssemblyVersion、AssemblyFileVersion、`Version`（x.y.z.0）和 `DisplayVersion`（x.y.z）。
2. macOS 端用 `scripts/dmg.sh` 生成 DMG，并用 `gh` 上传到草稿 Release `v<版本>`，同时给出 DMG 的 size 和 sha256。
3. 在 `windows/` 下运行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish-release.ps1 -MacSize <字节数> -MacSha256 <小写哈希>
   ```

   脚本依次：构建 Setup（含自动检查与自检）→ 从草稿下载 DMG 并核对 size/sha256 → 在内存中解密 DPAPI 私钥，签名 `latest-windows.json`、`latest-macos.json` 和 1.2.0 兼容 `latest.json` 并本地验签 → 把安装包复制到 `public/` → 上传 Setup 与两份清单到草稿 → 原子切换自建服务清单 → 草稿转正式 → 从自建服务和 GitHub 各下载一次验签并核对哈希。正式发布后的任何失败都会恢复自建清单并把 Release 改回草稿。相同版本不得以不同内容重新发布。
4. 先用 `-DryRun`（可配合测试密钥与 `-MacDmg` 本地文件）在本机演练：只构建、签名、本地校验，不上传。

签名私钥保存在发布账户的 `%LOCALAPPDATA%\ClaudeLauncher-Publisher\signing-key.dpapi`，由 Windows DPAPI CurrentUser 加密，只在内存中解密，不写明文、不进日志。不要复制到 `public/`、仓库或发给客户。`assets/update-public-key.xml`（RSA-3072）是公开校验密钥，两端客户端都内置它。不要重建密钥，否则旧客户端无法接受新包；迁移发布电脑必须专门处理密钥迁移，单纯复制 DPAPI 文件不能保证解密。
